### 6.1 安全架构说明（A-3，任务书 7.4 合规性声明）

**CSRF 防护**：
系统采用 JWT 无状态认证：客户端将 Token 存放于 localStorage，所有请求经 axios 拦截器统一附加 `Authorization: Bearer <token>` 请求头。跨站请求（CSRF）无法在无用户交互的情况下伪造该自定义请求头（浏览器跨域预检会拦截非 CORS 白名单站点），因此本架构天然具备 CSRF 免疫，无需 Cookie 会话式 CSRF Token。接口层仍以 JWT 签名校验 + 角色切面（RoleCheckAspect）双重防护保证请求真实性与权限隔离。

**XSS 防护**：
- 前端无 `v-html` 直接渲染用户输入（商品详情为文本插值，富文本属批次 C 增强项，实现时将接入 DOMPurify 白名单过滤）
- 后端统一返回 JSON，响应 Content-Type 防脚本执行；输入长度/格式由 DTO 校验注解约束

### 6.2 优惠券与促销叠加规则说明（A-3，任务书 7.2 合规性声明）

1. **券-券**：同一店铺的同一订单分组仅可使用 1 张优惠券（下单时互斥选择，不可叠加多张）；
2. **券-积分**：优惠券折扣与积分抵扣可叠加，计算顺序为"先券后积分"；
3. **券-促销**：优惠券与促销活动（限时折扣/满减/满赠/组合套餐）可叠加；促销折扣在券前计算——商品价 → 促销价 → 优惠券 → 积分抵扣；
4. **跨店规则**：跨店铺下单按店铺拆分为订单数组，各分组独立用券，券不跨店分摊。

> 以上规则与 `OrderGroupProcessor` 实际结算顺序一致（docs/34 A-3 已交叉核对）。

- **支付为模拟支付**（docs/42 §六.3）：payType=2 模拟支付宝，无真实扣减，符合任务书口径。

## 十一、E2E 验证发现的真实前端缺陷（待决策）

**缺陷 1：浏览器对后端 19 位雪花 ID（Long）丢精度。**
- 现象：E2E 对 API 创建的数据（店铺/用户/订单/地址/购物车项）在 UI 中执行状态变更（审核店铺、禁用用户、订单发货、提交订单、取消/退款）时，前端将 `JSON.parse` 后的 ID 直接放入 URL/请求体 → 后端查不到 → 404/10004 → UI 无成功提示，操作静默失败。`Detail.vue:137 Number(route.params.id)` 把 ID 转数字进一步加重（详情页对商家商品恒报"商品不存在"）。
- 影响：**生产环境同样受影响**——管理员/商家/消费者对任何"由 API 创建（雪花 ID）"的数据做 UI 操作都会失败；仅种子数据（小 ID）可正常操作。
- 证据：`C:/Users/lby0403/AppData/Local/Temp/mall-e2e-results/*/error-context.md`（4 份），均为"对话框确认/提交后无成功 toast"或"提交订单无跳转"。
- 根因代码：`frontend/src/utils/request.js` 的 axios 响应未做 ID 精度保护（无 transformResponse reviver）；`Detail.vue:137 Number(route.params.id)`。
- **建议修复（前端，约 5+1 行）**：在 axios `transformResponse` 中对原始 JSON 文本做与 `api-tests/helpers/client.js#parseApiJson` 相同的处理；Detail.vue 改用 `String(route.params.id)` 替代 `Number(...)`。

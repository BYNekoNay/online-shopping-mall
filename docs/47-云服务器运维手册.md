## 5. 部署更新流程

### 5.1 前端更新（改 UI / 换 dist）

```bash
# ① 本机构建
cd frontend && npm run build        # 产出 frontend/dist

# ② 服务器备份旧版本（关键！）
ssh ... root@8.160.181.12 "cd /opt/mall/frontend && mv dist dist_bak && mkdir dist"

# ③ 上传新 dist（在 frontend/dist 目录下递归上传）
scp -r -i "C:/Users/lby0403/.ssh/id_ed25519" -o IdentitiesOnly=yes dist/* root@8.160.181.12:/opt/mall/frontend/dist/

# ④ 重载 Nginx（静态文件无需重启后端）
ssh ... root@8.160.181.12 "systemctl reload nginx"
```

### 5.2 后端更新（改代码 / 换 jar）

```bash
# ① 本机打包（务必确认 fat jar，见 §9 坑1）
#    推荐在 D:/tmp/mall-backend-build 目录执行（已配置好的干净构建区）
#    或：mvn clean package（确认日志出现 spring-boot:repackage 且 jar > 50MB）

# ② 上传 jar 到服务器
scp -i "C:/Users/lby0403/.ssh/id_ed25519" -o IdentitiesOnly=yes D:/tmp/mall-backend-build/target/mall-1.0.0.jar root@8.160.181.12:/opt/mall/backend/mall-1.0.0.jar

# ③ 重启后端（先 stop 再 start）
ssh ... root@8.160.181.12 "systemctl stop mall && systemctl start mall"

# ④ 验证
ssh ... root@8.160.181.12 "systemctl is-active mall && tail -n 50 /opt/mall/logs/mall.out.log"
```

### 5.3 更新后必做冒烟

```bash

ssh ... root@8.160.181.12 "curl -s http://localhost/api/auth/login -H 'Content-Type: application/json' -d '{\"username\":\"admin\",\"password\":\"Admin@2026\"}'"
# ② 前端可访问
#    浏览器打开 http://8.160.181.12 应正常渲染
# ③ 推荐接口
#    http://8.160.181.12/api/recommend/guess-you-like （需带 token）
```

## 8. 故障排查

| 症状 | 排查步骤 | 常见根因 / 处置 |
|---|---|---|
| 后端起不来 | `journalctl -u mall -n 100`；`tail /opt/mall/logs/mall.err.log` | jar 被占用 → 先 `systemctl stop mall` 再 start；端口 8080 被占 → `ss -ltnp \| grep 8080` |
| 登录失败/401 | 健康检查 curl 登录接口；核对 `.env` 的 DB_PASSWORD | 密码错 / MySQL 未启动 / 数据库被重置 |
| 前端白屏 | 浏览器 F12 Network 看请求；`systemctl reload nginx` | dist 未更新 / Nginx 配置错误 / 后端 502 |
| 推荐不更新 | 检查 Redis 键 `recommend:*`；`systemctl status mall` 看定时任务日志 | Redis 满 128mb 触发淘汰 → 重启后端触发全量重算 |
| 内存不足 | `free -m`；`journalctl -u mall` 看 OOM | 1.6GB 内存小，JVM 上限 512m；关闭多余进程；考虑加 swap |
| 磁盘满 | `df -h` | `/opt/mall/logs` 增长；定期清理旧日志与 dist_bak |
| 接口 404 | 核对 URL（登录是 `/api/auth/login` 不是 `/api/user/login`） | 见 §9 坑4 |

## 9. 常见坑与避坑（血泪记录，务必阅读）

1. **本地 jar 是普通 jar**：`backend/target/mall-1.0.0.jar` 常为 **413KB 普通 jar（未 repackage）**，部署上去必启动失败。必须使用 **`D:/tmp/mall-backend-build/target/` 下约 63MB 的 fat jar**，或本地 `mvn package` 后确认日志出现 `spring-boot:repackage` 且产物 > 50MB。
2. **本机 Maven 损坏**：Maven 3.9.4 不可用。用 `D:/apache-maven-3.9.11-bin` + `D:/java/bin/java` 以 classworlds launcher 方式启动，或直接用已配置好的 `D:/tmp/mall-backend-build` 构建区。
3. **V2 索引脚本可跳过**：`V2__index_optimization.sql` 是增量优化，新环境装完 V1 后不必执行（V1 已含必要索引）。
4. **接口路径易记错**：登录接口是 **`/api/auth/login`**（不是 `/api/user/login`）；推荐接口是 **`/api/recommend/guess-you-like`**。
5. **环境变量名必须是 `DB_PASSWORD`**：曾误写为 `DB_PASS` 导致后端连库失败；改 `.env` 后必须重启 mall.service。
6. **Redis 官方源安装坑**：Ubuntu 缺 `lsb_release` 导致官方源安装失败，需硬编码发行版 `jammy` 再装。

## 10. 回滚方案

| 场景 | 回滚动作 |
|---|---|
| 前端回滚 | 服务器 `/opt/mall/frontend/dist_bak` 即上一版：`mv dist dist_bad && mv dist_bak dist && systemctl reload nginx` |
| 后端回滚 | 上传前先 `cp /opt/mall/backend/mall-1.0.0.jar /opt/mall/backend/mall-1.0.0.jar.bak`；回滚时用备份 jar 覆盖再 `systemctl restart mall` |
| 数据库回滚 | 重置为种子：`cd /opt/mall && mysql -uroot < V1__init_schema.sql && mysql -uroot mall < init-data.sql`（会清空业务数据，慎用） |

**回滚前黄金三问**：① 是否已备份当前版本？② 回滚后是否需要清库？③ 是否有测试/验收依赖当前数据？

## 一、目标与边界

### 1. 目标
对照验收材料（docs/42 终审报告的 69 功能点），在**不修改后端业务代码**、**不修改前端业务代码**的前提下，建立可重复执行的"接口测试 + 端到端 E2E"两层自动化体系，补齐既有 461 后端单测 + 42 前端单测之外的集成与系统测试空白。

### 2. 边界
- **不触碰**：backend/src/main 与 frontend/src 业务代码
- **可新增/修改**：测试资产、2 个配置文件（package.json、vitest.config.js / vitest.api.config.js、eslint.config.js、e2e/playwright.config.js）、reset 脚本
- **依赖最小化**：E2E 仅 `@playwright/test`；接口测试零新增依赖（用 Vitest + Node 内置 fetch）

### 3. 关键事实（已与项目状态对齐）
- **支付是模拟支付**：`OrderService.pay` 的 `payType` 仅支持 1(余额)/2(模拟支付宝)，无真实扣减。E2E 统一使用 `payType=2`。
- **种子数据无商家账号**：仅 `admin/Admin@2026`(管理员) 与 `testuser/Mall@2026`(消费者)。E2E 商家一律自建（注册→管理员分配角色→入驻申请→管理员审核通过）。
- **token 存 localStorage**：键为 `token / userId / role / nickname / user`（与 `src/store/user.js` 一致）。
- **接口契约**：`{code, message, data}`；分页 `{records, total, pageNum, pageSize, pages}`；错误码表见 docs/09 §4。
- **在线测试环境**：`http://8.160.181.12`（Nginx 反代 `/api → 8080`，已运行）；可改 `E2E_BASE_URL` / `API_BASE_URL` 环境变量切换。

## 五、关键工程决策

### 1. 雪花 ID 精度保护（`api-tests/helpers/client.js` + `e2e/helpers/accounts.js`）
后端主键用 MyBatis-Plus 雪花 ID（19 位），超过 JS 安全整数 2^53，直接 `JSON.parse` 丢精度导致按 ID 操作的请求 404。
**做法**：在原始 JSON 文本中将 `"*Id"` 键 + 15 位以上数字改写为字符串后再 parse；同时对 `"data": <15 位以上裸数字>`（如 `POST /user/addresses` 返回 `data=addressId`）做同样处理。
验证：95/95 接口用例全绿、20/20 E2E 全绿（修复后）。

### 2. 商家账号 E2E 自建（用户已确认）
后端 `UserService.register` 永远写 `role=1`，且 `ShopController` 类级 `@RequireRole(2)` 拦截消费者直接入驻。唯一可行链路：注册→**管理员 `PUT /api/admin/users/{id}/role` 分配 role=2**→商家重新登录（取带角色声明的 JWT）→`POST /api/merchant/shop/apply`→管理员 `PUT /api/admin/shops/{id}/audit {approved:true}`。
封装在 `e2e/helpers/accounts.js#createMerchantWithShop` 与 `api-tests/helpers/accounts.js#createMerchant`，被 11 个商家/管理用例与 1 个 E2E 用例复用。

### 3. 模拟支付贯穿 E2E（用户已确认）
支付用 `payType=2 模拟支付宝`（无需真实余额、也避开登录限流副作用），`OrderService.pay` 不做实际扣减 → 直接返回 `paySuccess=true`。

### 4. Playwright 浏览器复用本机已装的 chromium-1234
`@playwright/test@1.62.1` 内置 browsers.json 指定 chromium revision 1234，与 `~/AppData/Local/ms-playwright/chromium-1234` 完全匹配，零下载。
**安装**：因 npm cache 的 `safe-delete` 在本机 sandbox 受限（连续 EPERM），采用 `curl` 直接下载 npmmirror 上的 `playwright-core-1.62.1.tgz` / `playwright-1.62.1.tgz` / `@playwright/test-1.62.1.tgz`，手工 `tar -xzf` 到 `node_modules/`，更新 `package.json` 中 devDependencies 与 scripts。功能与 `npm install` 等价，可重复。

### 5. 默认 vitest 与接口 vitest 配置分离
- `vitest.config.js`：jsdom + vue plugin，扫描 `src/__tests__/**`（既有 42 用例）
- `vitest.api.config.js`：node 环境 + `api-tests/**`（95 用例）
两者通过 `exclude` 互不干扰，`npm test` 跑默认、`npm run test:api` 跑接口、`npm run test:all` 串联三者。

### 6. 登录限流容错
系统自带 `LoginAttemptService`（同 IP+用户 5 次失败 / IP 累计 30 次失败锁 15 分钟），`AUTH-02/03/ADMIN-03` 的负向断言接受 `[20001/20002, 10005]`，确保在同一测试运行窗口内重复执行仍能通过。

### 7. E2E 商品规格自动选择
`ProductDetailPage.addToCart/buyNow` 进入详情页时先点击 `.sku-options .el-radio` 第一个规格（多规格商品默认按钮文案为"请选择规格"且禁用；不选规格直接 `getByRole('button', { name: /加入购物车/ })` 会误点相似推荐卡片的快速加入按钮，已实测验证此陷阱），主按钮通过 `.actions .el-button--primary` 精确定位。

### 8. 输出目录移出项目
`outputDir` 与 `reporter` 指向 `C:/Users/lby0403/AppData/Local/Temp/mall-e2e-*`，避免 `node_modules/.vite/vitest/results.json` 类被 sandbox 锁定导致 EPERM。

## 八、遗留与已知限制

1. **`node_modules/.vite/vitest/results.json` EPERM**：本机 sandbox 在 vitest 写入 results.json 时偶发 EPERM。已加 `cache: false` 缓解；首次构建若失败，删除 `node_modules/.vite` 即可。
2. **登录限流对全量重跑的影响**：在同一 IP 窗口内（15 min）多次完整运行，IP 累计失败接近 30 时可能触发 10005。已用 `[业务码, 10005]` 双值断言容错，不影响 95/95 通过。
3. **E2E 强依赖线上服务可用性**：本方案不配置 `webServer`（Nginx 已在生产持续运行）。若希望本机自跑全栈，需在 `playwright.config.js` 增加 `webServer` 段并调整 baseURL。
4. **未自动化：物流轨迹为模拟实现**（docs/18 已声明，真实对接需快递100企业版 API Key）。
5. **后端 461 单测 / 42 前端单测未在本次任务中运行验证**：属既有体系，本任务聚焦"补齐"。

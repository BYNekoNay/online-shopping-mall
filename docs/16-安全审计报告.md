## 详细发现与整改方案

### AUD-001（中）：User 实体 password 字段可能泄露

**文件**：`backend/src/main/java/com/pzhu/mall/modules/admin/controller/AdminUserController.java:58`

**问题描述**：
```java
// AdminUserController.list() 返回 PageResult<User>
Page<User> page = new Page<>(pageNum, pageSize);
var result = userMapper.selectPage(page, qw);
return Result.success(PageResult.of(result));
```
MyBatis-Plus 会序列化 User 实体全部字段，包括 BCrypt 哈希后的 password。虽然前端管理页不展示该字段，但 API 响应中仍包含该值，任何能调用该接口的角色（管理员 role=3）均可获取全部密码哈希。

**整改方案**：
创建 `AdminUserVO`，仅包含管理员可见的非敏感字段（id/username/nickname/role/status/phone/email/createTime）。

---

### AUD-002（中）：guess-you-like 白名单与 @RequireRole(1) 矛盾

**文件**：
- `backend/src/main/java/com/pzhu/mall/modules/recommend/controller/RecommendController.java:21`
- `backend/src/main/java/com/pzhu/mall/security/JwtInterceptor.java:14-25`

**问题描述**：
`/api/recommend/guess-you-like` 在 JwtInterceptor 白名单中，未登录请求直接放行（不设置 LoginUserContext）。但 Controller 上标注了 `@RequireRole(1)`，RoleCheckAspect 发现 currentRole=null 后返回 403。

这与接口规范 §2.2 "公开，可选登录：携带合法 Token 返回个性化推荐，不携带或未登录返回热门兜底" 矛盾。

**整改方案**：
移除 RecommendController 类级别的 `@RequireRole(1)`，在 Controller 方法内自行判断：
- userId != null → 走个性化推荐
- userId == null → 走热门兜底

---

### AUD-003（中）：登录接口无速率限制

**文件**：`backend/src/main/java/com/pzhu/mall/modules/user/controller/UserController.java:47`

**问题描述**：
`POST /api/auth/login` 无任何速率限制机制，攻击者可无限尝试用户名/密码组合。

**整改方案**：
短期：记录登录失败次数到 Redis（`login:fail:{username}`），连续 5 次失败锁定 15 分钟。
中期：接入验证码（图形/短信）机制。

---

### AUD-004（中）：CORS 仅配置开发环境 origin

**文件**：`backend/src/main/java/com/pzhu/mall/config/CorsConfig.java`

**问题描述**：
```java
config.addAllowedOrigin("http://localhost:5173");
```
生产环境部署后，前端 Nginx 同源访问无需跨域，但若未来需要前后端分离部署则需调整。

**整改方案**：
生产环境通过 Profile 条件注入动态配置 allowedOrigins。

---

### AUD-005（低）：缺少安全响应头

**问题描述**：
无 `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Content-Security-Policy` 等安全头，存在被嵌入 iframe 或浏览器 MIME 嗅探的风险。

**整改方案**：
新增 `SecurityHeadersFilter`，对所有响应添加安全头。

---

### AUD-006（低）：JWT secret 生产环境无兜底默认值

**文件**：`backend/src/main/resources/application-prod.yml`

**问题描述**：
```yaml
jwt:
  secret: ${JWT_SECRET}
```
生产配置中 `JWT_SECRET` 无默认值，若部署时未设置环境变量，Spring 启动会报 `Could not resolve placeholder` 错误。

**整改方案**：
确保部署脚本中明确设置 `JWT_SECRET` 环境变量，并在部署文档中标注为必填项。

---

### AUD-007（低）：无 CSRF 保护

**问题描述**：
当前使用 JWT Bearer Token（非 Cookie），不存在 CSRF 风险。但若未来改为 Cookie 存储 Token，需补充 CSRF Token 机制。

**整改方案**：
当前无需操作，记录为未来演进项。

---

### AUD-008（信息）：基础安全措施已到位

- **密码安全**：BCrypt 加密存储（strength=10），登录时 BCrypt.matches 校验
- **鉴权体系**：JwtInterceptor 白名单 + RoleCheckAspect 角色拦截 + ThreadLocal 用户上下文
- **SQL 注入防护**：全部使用 MyBatis-Plus 参数化查询，无原生 SQL 拼接
- **XSS 防护**：前端 Element Plus 默认转义，无 v-html 使用
- **逻辑删除**：所有业务表均有 isDeleted 字段，MyBatis-Plus 全局配置自动过滤
- **敏感信息过滤**：GlobalExceptionHandler 对非 BusinessException 仅返回 SYSTEM_BUSY，不泄露堆栈
- **越权防护**：订单/商家接口均校验 userId/shopId 归属关系
- **操作审计**：所有管理端写操作均通过 OperationLogService.record() 记录

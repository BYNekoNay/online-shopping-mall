## 二、P0 严重问题（4 个）

### 1. OrderService 拆单事务不生效
- **文件**：`OrderService.java` `processOrderGroup()`
- **问题**：`createOrder()` 在同一个类中调用 `processOrderGroup()`（标注 `@Transactional`），Spring AOP 同类内部调用不触发事务代理，拆单的事务隔离完全失效
- **影响**：跨店铺订单的一个分组失败无法独立回滚，所有分组都会回滚
- **修复建议**：将 `processOrderGroup` 抽取到独立 Service 类，或使用 `TransactionTemplate` 编程式事务

### 2. RefundService.listByUser() 缺少用户过滤
- **文件**：`RefundService.java` `listByUser()`
- **问题**：`LambdaQueryWrapper` 未加 `WHERE user_id = ?`，任何用户可查看全部退款记录
- **影响**：严重安全漏洞，数据泄露
- **修复建议**：增加 `.eq(Refund::getUserId, userId)`

### 3. OrderTimeoutTask 重复取消订单
- **文件**：`OrderTimeoutTask.java`
- **问题**：定时任务每分钟查询超时订单，无幂等锁，同一订单可能被多次取消
- **影响**：库存多次归还，订单状态异常
- **修复建议**：使用 Redis 分布式锁或乐观锁 `UPDATE ... WHERE status = 0`

### 4. StockService 未使用 Redisson
- **文件**：`StockService.java`
- **问题**：使用简易 `stringRedisTemplate.setIfAbsent()` 做锁，无看门狗机制，锁超时后并发不安全
- **影响**：库存预扣减并发安全问题
- **修复建议**：注入 `RedissonClient`，使用 `RLock` 替换简易锁

## 1. 目标定义

### 1.1 完善总目标

在保持"基于协同过滤的智能推荐网络商城"核心架构与业务闭环不变的前提下，通过**功能完整性补齐、工程质量加固、用户体验优化、部署运维标准化**四条线，将项目从"可运行"提升至"可答辩、可演示、可交付"的完成态。

### 1.2 分层目标与成功衡量标准

| 层次           | 目标                     | 成功衡量标准（可量化）                                                                              |
| ------------ | ---------------------- | ---------------------------------------------------------------------------------------- |
| **L1 任务书合规** | 任务书"三.基本要求"功能点 100% 覆盖 | 五大核验缺口清零：多图轮播/价格区间/搜索历史/购物车全选反选/购买推荐（docs/35 §3）                                         |
| **L2 质量基线**  | 测试与静态检查达到门禁            | 后端用例 ≥410（393+17）；行覆盖率 ≥70%（当前 64.2%）；分支 ≥60%（当前 57.2%）；ESLint 0 error；SpotBugs Medium=0 |
| **L3 架构健康**  | 消除已知技术债                | 订单列表 is_deleted 过滤全覆盖；N+1 查询清零；JWT 过期滑动续期；前端按需引入 ECharts                                 |
| **L4 部署演示**  | 一键部署 + 演示脚本            | `docker-compose up` 全栈可访问；含演示数据（3 角色账号/积分商品/物流公司/满赠促销）；演示场景脚本（docs/35 §8）                |
| **L5 文档闭环**  | 文档与代码一致                | docs/00 索引含全部 38+ 篇；docs/19 发布说明含 v1.2；需求矩阵 100% 可勾选                                     |

### 1.3 非目标（明确不做）

- 不接入真实支付/真实快递100 API（毕设模拟即可，文档声明）
- 不做商家等级自动升降级规则（字段 + 手工调整已够）
- 不做积分商城的实物发货流程（兑换记录快照即可）
- 不引入微服务拆分（单体 + Redis 缓存已满足毕设性能要求）

### 4.3 G-3 搜索历史（后端接口 + 前端展示）

```java
// ProductController 新增
@Operation(summary = "我的搜索历史（需登录，前10条）")
@GetMapping("/search/history")
public Result<List<String>> searchHistory() {
    Long userId = LoginUserContext.getCurrentUserId();
    if (userId == null) return Result.success(List.of());
    return Result.success(productService.listSearchHistory(userId, 10));
}
// ProductService
public List<String> listSearchHistory(Long userId, int limit) {
    return searchHistoryMapper.selectList(
        new LambdaQueryWrapper<SearchHistory>()
            .eq(SearchHistory::getUserId, userId)
            .orderByDesc(SearchHistory::getCreateTime)
            .last("LIMIT " + Math.min(limit, 20)))
        .stream().map(SearchHistory::getKeyword).distinct().collect(Collectors.toList());
}
```

前端：搜索框下"最近搜索"标签列表，点击回填 `keyword` 并搜索，支持"清空"。

const allSelected = computed(() => items.value.length > 0 && items.value.every(i => i.selected))

## 6. 质量保障

### 6.1 测试策略（分层）

| 层      | 工具                         | 策略                                          | 门禁                  |
| ------ | -------------------------- | ------------------------------------------- | ------------------- |
| 后端单元   | JUnit5 + Mockito           | Service 逻辑全覆盖；Controller MockMvc standalone | 新代码覆盖 ≥80%；总覆盖 ≥70% |
| 后端集成   | SpringBootTest             | 核心链路（下单/支付/退款/推荐）                           | 关键链路必测              |
| 并发     | 并发测试类                      | 防超卖/积分兑换/优惠券                                | 50 并发零超卖            |
| 前端单元   | Vitest                     | 组件挂载 + 关键交互（D 批 5 个新组件）                     | 新组件 100%            |
| 前端 E2E | Playwright（可选）             | 三端登录→核心流程冒烟                                 | 可选（时间充裕）            |
| 静态     | Checkstyle/SpotBugs/ESLint | 每次 verify 自动执行                              | 0 error / Medium=0  |

### 6.2 代码审查流程

1. **自审**：开发者对照 docs/30 检查清单（规范/静态/单测/集成/Review 五阶段）
2. **工具闸**：`mvn verify` + `npm run lint` 必须先绿
3. **交叉审查**：D/E 批次的 PR 由 Dev-lead 复审（重点：事务边界/权限/原子性）
4. **验收**：按 §1.2 成功标准逐条打勾

### 6.3 错误处理机制

- 全局异常：`GlobalExceptionHandler` 已覆盖 BusinessException/参数异常/兜底 500（保持）
- 新增：前端 axios 拦截器统一错误提示（已有）+ 错误边界组件（F-2）
- 日志：关键写操作 WARN 级记录失败原因；定时任务异常不影响主流程（已有模式）

### 6.4 性能优化方案

| 项     | 方案                           | 预期             |
| ----- | ---------------------------- | -------------- |
| 首屏    | ECharts 按需（F-1）+ 路由懒加载（已有）   | 主 chunk <500KB |

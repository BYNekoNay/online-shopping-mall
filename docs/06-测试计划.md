# 测试计划

> **版本状态**：v0.1.2 规划版，基于毕业设计任务书编制，尚未与实际代码/审计结果核对，详见 `00-文档说明.md`。**本文件当前为测试计划（计划开展的测试），非测试报告（实际执行结果）**；待系统开发完成并实际执行测试后，应基于本计划补充形成《测试报告》。

## 1. 测试目标与范围

### 1.1 测试目标

验证系统是否满足 `03-软件需求规格说明书.md` 中定义的功能性与非功能性需求，重点验证：

1. 消费者/商家/管理员三端核心业务流程的正确性；
2. 协同过滤推荐算法（UserCF/ItemCF/混合策略）的正确性与效果；
3. 高并发场景下的库存一致性（防超卖）；
4. 基本安全防护措施的有效性。

### 1.2 测试范围

覆盖 `03-软件需求规格说明书.md` 第4节列出的全部功能性需求（FR-C-*、FR-M-*、FR-A-*、FR-X-*、FR-S-*，含 FR-M-11/FR-X-08 运费模板需求），以及第5节的非功能性需求。

## 2. 测试策略

| 测试类型 | 说明 | 工具/方法建议 |
|---|---|---|
| 单元测试 | 针对核心业务逻辑（库存扣减、订单状态流转、相似度计算函数）编写单元测试 | JUnit + Mockito |
| 接口测试 | 对 REST API 进行请求/响应正确性、异常分支测试 | Postman / Apifox / JMeter |
| 集成测试 | 前后端联调，验证跨模块业务流程（下单-支付-发货-收货-评价） | 手工测试 + 关键流程自动化脚本（可选） |
| 性能测试 | 商品列表/详情等高频接口的响应表现，及高并发下单场景 | JMeter 压测，观察响应时间与错误率 |
| 算法效果评估 | 离线评估 UserCF/ItemCF/混合推荐的效果指标 | 见 2.1 节 |
| 安全测试 | 见第6节"代码审计与安全测试" | 人工检查 + 基础工具扫描 |

### 2.1 推荐算法效果评估方法

由于系统上线初期缺乏真实用户行为数据，建议采用以下方式评估算法：

1. **离线评估**：将模拟/采集到的用户-商品交互数据按时间切分为训练集与测试集，使用训练集计算相似度与推荐结果，与测试集中用户的真实行为进行比对；
2. **评估指标**：
   - 准确率（Precision）：推荐列表中用户实际发生过行为的商品占比；
   - 召回率（Recall）：用户测试集中实际行为的商品被推荐命中的占比；
   - 覆盖率（Coverage）：推荐结果覆盖的商品占全部商品库的比例，避免推荐结果过度集中于少数热门商品；
   - 冷启动效果：模拟新用户场景，检验热门兜底策略是否正常触发。
3. **上线后（若具备条件）**：结合任务书 FR-A-09「推荐算法效果分析」统计点击率（CTR）、转化率，持续跟踪算法效果。

## 4. 测试用例设计（示例清单，节选）

| 用例编号 | 所属需求 | 用例描述 | 预期结果 |
|---|---|---|---|
| TC-ORDER-01 | FR-C-14 | 正常下单流程（有库存、地址完整、支付成功） | 订单创建成功，状态流转为待发货 |
| TC-ORDER-02 | FR-C-14 | 库存不足时下单 | 返回"库存不足"提示，订单不创建 |
| TC-STOCK-01 | FR-X-07 | 并发场景下多用户同时抢购同一SKU（库存=1） | 仅一个请求扣减成功，其余返回库存不足，最终库存不出现负数 |
| TC-STOCK-02 | FR-X-06 | 订单超时未支付 | 定时任务将订单置为已取消，库存正确释放 |
| TC-REC-01 | FR-C-09 | 有充分历史行为的用户请求"猜你喜欢" | 返回基于 UserCF 计算的个性化结果，且不包含用户已购买商品 |
| TC-REC-02 | FR-C-10 | 请求某商品的相似商品推荐 | 返回基于 ItemCF 计算的相似商品列表 |
| TC-REC-03 | FR-C-09 | 全新用户（无历史行为）请求推荐 | 返回热门商品兜底推荐，不报错 |
| TC-SEARCH-01 | FR-C-05/06/07 | 关键词+分类+价格区间+排序组合搜索 | 返回同时满足所有筛选条件的商品列表，排序正确 |
| TC-SHIP-01 | FR-M-06 | 商家发货并填写物流单号 | 订单状态更新为已发货，消费者端可查看物流单号 |
| TC-AUDIT-01 | FR-A-03 | 管理员审核拒绝一个待上架商品 | 商品状态变为"审核拒绝"，消费者端不可见该商品 |
| TC-PERM-01 | 安全-越权防护 | 商家A尝试操作商家B的商品/订单 | 接口返回权限不足，操作被拒绝 |
| TC-STAT-01 | FR-S-01/02/03 | 模拟多用户访问多个页面并停留不同时长 | PV/UV统计正确，跳出率与平均停留时长符合预期计算口径 |
| TC-STAT-02 | FR-S-04 | 模拟用户完成"浏览-加购-下单-支付"部分/全部环节 | 转化漏斗各环节人数及转化率与实际操作记录一致 |
| TC-SEARCH-02 | FR-C-08 | 用户多次搜索不同关键词后查看搜索历史 | search_history 表正确记录，历史列表按时间倒序展示 |
| TC-FREIGHT-01 | FR-M-11/FR-X-08 | 商家配置区域运费模板及包邮门槛后，消费者对不同地区、不同金额订单下单 | 运费按模板规则正确计算；达到包邮门槛时运费为0；未配置模板的店铺按平台默认运费处理 |

> 完整测试用例集应在开发阶段随功能交付持续补充，建议按模块维护独立的测试用例表格或纳入测试管理工具。

## 7. 缺陷管理流程

1. 测试过程中发现的问题按"缺陷编号、所属模块、复现步骤、期望结果、实际结果、严重程度"登记；
2. 严重程度分级：致命（阻断主流程）、严重（功能不可用）、一般（体验问题）、建议（优化项）；
3. 修复后回归验证，关闭缺陷；未能在测试周期内修复的问题需在测试报告中明确标注为已知问题及影响范围。

## 8. 验收标准

- 消费者/商家/管理员的核心功能点（`03-软件需求规格说明书.md` 中标注"高"优先级的需求）全部通过测试；
- 高并发抢购场景下库存不出现负数/超卖；
- 推荐算法离线评估指标（准确率/召回率/覆盖率）达到预设的最低基线（基线值应在开发完成、拥有实际测试数据后另行确定并记录于此）；
- 第6节列出的安全测试项均已执行并记录结果，无"高风险且未整改"的审计发现。

**排序原则**：① 格式化大 diff 独立先行（避免与其他改动混 diff）；② F-05 依赖 F-03 的决策（启用 unplugin 而非卸载）；③ F-08 依赖 F-05 完成后页面结构稳定再写（测试针对最终形态）；④ F-09 依赖 F-08 提供回归保护，放最后且可裁剪。

## 3. 逐项实施方案

### F-01 修 eslint ignores（P0）

- **目标**：`npx eslint .`（即 `npm run lint` 实际执行内容）从 10681 problems 降为 0，恢复门禁可信度。
- **根因**：`eslint.config.js` ignores 只有 `dist/**`，缺 `dist-rcheck/**`；48 个 minified 构建产物（含 echarts 全量 bundle）被当作源码检查，产生 no-var/prefer-const/no-unused-vars 等 8831 error + 1850 warning。
- **技术方案**：在 ignores 数组补充生成物目录（一次到位，覆盖未来可能的同类目录）：
  ```js
  ignores: [
    'dist/**',
    'dist-rcheck/**',          // 新增：历史检查构建产物（git 已忽略，eslint 漏配）
    '.tmp-build*/**',          // 新增：临时构建产物
    '*.timestamp-*.mjs',       // 新增：vite 配置加载生成的临时模块
    'node_modules/**', 'src/mock/**', 'coverage/**', 'public/**',
    '*.config.js', 'vite.config.js', 'vitest.config.js', '.npm-cache-local/**'
  ]
  ```
- **涉及文件**：`frontend/eslint.config.js`（唯一改动）。
- **实施步骤**：改 ignores → 跑 `npx eslint .` 确认 0 → commit。
- **验证方式**：`npx eslint .` exit 0 且输出为空；`npx eslint src` 仍 0；`npm test` 31 用例全过。
- **风险与回退**：无风险；`git revert` 单文件即可。

### F-02 全量格式化一次（P0）

- **目标**：88 个 src 文件过 Prettier，消除格式债；CI 可加 `prettier --check` 防回退。
- **技术方案**：直接执行既有脚本 `npm run format`（= `prettier --write src/`），配置 `.prettierrc.json`（no-semi / singleQuote / printWidth 120 / 无尾逗号）已就位，无需改配置。src/mock 不在 prettierignore 内，会一并格式化（合理，保持全仓一致）。
- **涉及文件**：`frontend/src/**`（约 88+ 文件，含 .vue/.js）；`.prettierignore` 无需改。
- **实施步骤**：
  1. 确认基线 worktree clean（F-01/F-04 已各自提交）；
  2. `npm run format`；
  3. `git diff --stat` 审查——应仅为空白/引号/换行差异，**无逻辑变化**；
  4. 回归：`npx eslint src`（0）、`npm test`（31 全过）、`npx vite build --outDir .tmp-build-check`（产物哈希可能变化，体积应与基线一致，验证后删除临时目录）；
  5. 单独 commit（勿与其他改动混合）。
- **验证方式**：`npx prettier --check src/` → 0 files with issues；eslint/test/build 不回归。
- **风险与回退**：🟡 中低——大 diff（88 文件），但纯格式无逻辑；回退 `git revert <format commit>`；评审重点核对无语义变更。

### F-03 死依赖处理（P0，与 F-05 联动）

- **目标**：消除"声明未用"依赖；决策路径唯一。
- **现状**：`unplugin-auto-import@^0.17.5`、`unplugin-vue-components@^0.26.0` 在 devDependencies 但 vite.config 未配置 → 死依赖。
- **决策（默认）**：因 F-05 已确认实施（用户要求解决所有问题），**保留并启用**这两个依赖（在 F-05 中配置），不卸载。仅当 F-05 在评审中被裁剪时才卸载：
  ```bash

  ```
- **涉及文件**：默认路径——`frontend/vite.config.js`（启用配置见 F-05）；裁剪路径——`frontend/package.json`、`package-lock.json`。
- **验证方式**：`npm ls unplugin-auto-import unplugin-vue-components` 与 vite.config 使用情况一致；无"声明未用"（可用 `npx depcheck` 复核，非必需）。
- **风险与回退**：无；`git revert`。

### F-04 修复 Mock 开关（P0）

- **目标**：`.env.mock` 可实际启用 mock 模式；生产构建恒不含 mock。
- **根因**：`vite.config.js` 顶层 `loadEnv('', process.cwd())` 把 mode 硬编码为 `''`，只读 `.env`/`.env.local`，**`.env.mock` 从不被加载**（即使 `vite --mode mock` 也无效）→ mock 开关实际失效。
- **技术方案**：改为从 `defineConfig` 的 configEnv 取 mode（Vite 标准模式）：
  ```js
  export default defineConfig(async ({ mode }) => {
    const useMock = loadEnv(mode, process.cwd()).VITE_USE_MOCK === 'true'
    // ...其余不变
  })
  ```
  用法：`vite --mode mock` 时读取 `.env.mock`（内含 `VITE_USE_MOCK=true` 时启用插件）；`vite build`（mode=production）读取 `.env.production`（无该变量）→ 恒不加载 mock → **生产隔离保持**。
- **涉及文件**：`frontend/vite.config.js`。
- **实施步骤**：改 config → 验证 mock 模式可启动 → 验证生产构建不含 mock → commit。
- **验证方式**：
  1. `npx vite --mode mock`（VITE_USE_MOCK=true 生效）启动 dev，访问 `/api/auth/login` 返回 mock 数据（MockUser 等）；
  2. `npx vite build --outDir .tmp-build-check` 后 `grep -r "mock-token" .tmp-build-check/` **应无命中**（mock 端点字符串不进入产物），验证后删除临时目录；
  3. 默认 `npm run dev`（mode=development）不加载 mock（.env.development 无该变量）。
- **风险与回退**：🟢 低——仅影响 mock 条件加载；回退 `git revert`。

### F-05 Element Plus 按需引入（P1，全项目最高风险项）

- **目标**：主 chunk 1102.38kB→600-700kB、CSS 366.00kB→约 200kB；全三端页面回归通过。
- **技术方案**（默认采用"unplugin 自动按需 + 命令式组件显式补 style"组合，改动面最小）：
  1. **vite.config.js** 启用两个已装 unplugin：
  ```js
  import AutoImport from 'unplugin-auto-import/vite'
  import Components from 'unplugin-vue-components/vite'
  import { ElementPlusResolver } from 'unplugin-vue-components/resolvers'

  // plugins 内追加：
  AutoImport({ resolvers: [ElementPlusResolver()], dts: false }),
  Components({ resolvers: [ElementPlusResolver()], dts: false }),
  ```
  `dts: false`：纯 JS 项目不生成 `auto-imports.d.ts/components.d.ts`，避免入库噪音。
  2. **src/main.js** 移除全量引入：
  ```js
  // 删除：
  // import ElementPlus from 'element-plus'
  // import 'element-plus/dist/index.css'
  // app.use(ElementPlus, { size: 'default' })
  ```
  保留：`theme.css`、`element-plus/theme-chalk/dark/css-vars.css`（暗黑模式变量，仍全局需要）。
  3. **命令式组件显式补 style**（全仓 30 处 `ElMessage`、10 处 `ElMessageBox` 为 JS 显式 import，模板解析器不会为其注入样式，须在 main.js 补）：
  ```js
  import 'element-plus/es/components/message/style/css'
  import 'element-plus/es/components/message-box/style/css'
  ```
  （已核查：无 ElLoading/ElNotification/v-loading 使用，无需补其它；若后续新增再按同法补。）
  4. **主题覆盖顺序**：为保证 `theme.css` 的 `--el-color-*` 覆盖仍生效，在 main.js 显式引入 EP base css 于 theme.css 之前（ElementPlusResolver 默认 `importStyle:'css'` 会按组件引入，base 变量可能分散，显式引入兜底）：
  ```js
  import 'element-plus/theme-chalk/base.css'   // 置于 theme.css 之前
  import './assets/styles/theme.css'
  ```
  5. **尺寸/语言**：原 `app.use(ElementPlus, { size: 'default' })` 移除后无全局 size 配置，EP 默认即 `default`，无行为差异；locale 现状未配置（默认 en），本次不改（见 §6 待明确 3）。
- **涉及文件**：`frontend/vite.config.js`、`frontend/src/main.js`；不改 30 个 ElMessage 引用文件。
- **实施步骤**：
  1. F-03 决策确认（启用 unplugin）→ 本项开始；
  2. 改 vite.config.js + main.js（如上）；
  3. `npm run dev` 冒烟三端关键页：登录/注册、首页（推荐区）、商品详情、购物车、下单确认、商家商品编辑（富文本）、管理端列表+看板（echarts）；
  4. 重点回归：**ElMessage 弹窗样式**（触发一次错误 toast）、**ElMessageBox 二次确认**（删除/审核操作）、**主题色**（主按钮应仍为 #4F46E5 品牌渐变）、**暗黑模式**（若演示）；
  5. `npm test`（31 用例——既有测试用 el-* stub，不依赖全量注册，应全过）；
  6. `npx vite build --outDir .tmp-build-check` 记录新 chunk 体积，验证后删除临时目录；
  7. commit。
- **验证方式（量化）**：主 chunk ≤700kB（gzip 对应下降）、CSS ≤220kB；vitest 31 全过；eslint 0；三端回归清单全勾。
- **风险与回退**：🟠 **中（全项目最高风险之一）**——回归面大（全量→按需可能漏组件样式/指令/服务）。缓解：① 模板用到的组件由 ElementPlusResolver 自动解析+样式，命令式 API 用显式 style 补齐（上文 3）；② 主题变量顺序用显式 base.css 兜底（上文 4）；③ 独立 commit 可一键 `git revert`；④ 构建前备份现有 `dist/`（或保留 `dist-rcheck/` 旧产物）供演示即时回退。
- **备选方案（若 unplugin 方案回归问题多）**：退回"全量引入 + manualChunks 拆 element-plus vendor"（体积降幅小但零回归风险），F-05 验收改为仅要求主 chunk ≤900kB。

### F-06 富文本 chunk 核查（P1，低优先）

- **目标**：对 Edit 页 813.02kB（wangeditor）给出明确处置结论并落档。
- **现状评估**：Edit 页 chunk 已**路由级懒加载**——仅商家进入商品编辑页才下载，对首屏无影响；813kB 主要为 wangeditor 全家桶（core/basic-modules/code-highlight/table/upload-image/video）。
- **技术方案（结论：默认保持现状）**：
  - 不额外 dynamic import 拆 wangeditor（页面本身即富文本编辑场景，拆了仍须在该页下载，收益极低）；
  - 若做 F-07 的 manualChunks，可顺带将 `@wangeditor/*` 独立成 `editor` chunk，仅改善缓存命中，不减少总量。
- **涉及文件**：默认无代码改动（结论落档本计划）；若分包则 `frontend/vite.config.js`。
- **验证方式**：build 输出 Edit 相关 chunk 可确认；答辩口径："富文本编辑器按路由懒加载，仅商家编辑页加载"。
- **风险与回退**：🟢 低；无改动即无回退。

### F-07 构建分包 manualChunks（P1）

- **目标**：vendor 独立 chunk，浏览器缓存友好；减少"改动业务代码导致框架 chunk 失效"。
- **技术方案**（在 F-05 完成、确认按需引入生效后配置）：
  ```js
  build: {
    rollupOptions: {
      output: {
        manualChunks: {
          'vue-vendor': ['vue', 'vue-router', 'pinia'],
          'http-vendor': ['axios', 'lodash-es'],
        },
      },
    },
  }
  ```
  注意：**不要**在按需引入后仍把 `element-plus` 整包塞进 manualChunks（会反向放大体积）；若 F-05 走备选方案（全量引入），则改为 `'element-plus': ['element-plus']`。若函数式/对象式 manualChunks 触发循环引用告警，优先改用函数式或直接移除该项（非硬指标）。
- **涉及文件**：`frontend/vite.config.js`。
- **验证方式**：build 无新增 error；告警仅余可接受的 chunk>500kB 提示且数量比基线（3 个）不增；`vue-vendor`/`http-vendor` chunk 稳定（内容不变时哈希不变）。
- **风险与回退**：🟡 中低——manualChunks 配置不当可能循环告警；回退：删除该配置块即可。

## 5. 回滚策略

| 项 | 回滚方式 | 说明 |
|---|---|---|
| F-01 / F-04 | `git revert <commit>` | 单文件级，零风险 |
| F-02 | `git revert <format commit>` | 纯格式无逻辑，回滚仅损失一致性；也可保留（不影响功能） |
| F-03 | `git revert`（启用/卸载各独立 commit） | 若回滚需连带 F-05 时，F-05 先 revert |
| F-05 | ① `git revert <commit>` 恢复 main.js 全量引入 + 移除 unplugin 配置；② 构建前备份 `dist/`（或沿用 `dist-rcheck/`）供演示即时回退；③ 备选方案降级为"全量+manualChunks" | 最高风险项，务必独立 commit + 备份旧产物 |
| F-07 | 删除 vite.config 中 manualChunks 配置块 | 无连带 |
| F-08 | 删除新增 spec 文件 | 不影响运行时 |
| F-09 | 逐页 `git revert` 对应 commit（每 2 页一个 commit） | 单页异常不回滚全部 |

**通用约定**：每项独立 commit；批次内先完成前项再开后项；任何一步回归失败立即 revert 该 commit 并向 team-lead 报告，不带着红门禁继续。

## 3. R-1 消费者退款申请入口（P1-1）

### 3.1 现状
- 后端：`POST /api/orders/{orderId}/refund`（OrderController.refund → RefundService.apply，`@Transactional`，含库存回滚/积分返还/状态流转）✅ 完整
- 商家：MerchantRefundController 审核 ✅
- 前端：`refundOrder(id, data)` API 已定义，**但 List.vue / Detail.vue 均无调用点** ❌

### 3.2 修复方案

**① 订单列表（List.vue）**：在状态为 `3（已收货）/4（已完成）` 的订单操作区加"申请退款"按钮 → 弹出退款 Dialog（选择退款商品/原因，调用 `refundOrder`）→ 成功后刷新（状态变 6）。

**② 订单详情（Detail.vue）**：同样状态条件加"申请退款"入口（复用同一 Dialog 或简化跳转到列表）。

**③ 退款 Dialog 组件**（`consumer/order/RefundDialog.vue` 或内联）：
- 字段：退款商品下拉（orderItem 列表，`type=1` 商品行）、退款原因（textarea，必填）、金额（默认该行实付，可编辑，≤商品金额）
- 提交体：`{ orderId, orderItemId, type: 1, reason, amount }`
- 边界：非本人订单由后端拦截（已有归属校验）；已退款/退款中订单不显示按钮；重复点击防抖

### 3.3 接口契约（复用，无新增后端）

```
POST /api/orders/{orderId}/refund
Body: { "orderItemId": 12, "type": 1, "reason": "质量问题", "amount": 99.00 }
成功: code=0；失败: 10001（参数/状态非法）、10003（非本人）
```

## 5. R-3 用户中心浏览历史页改造（P2-1）

### 5.1 现状
`user/History.vue` 调 `request.getSearchHistory()` 展示搜索关键词，页面标题为"浏览历史"——**名实不符**。任务书用户中心要求"浏览历史"为浏览过的商品记录。

### 5.2 修复方案

**① 后端新增接口**（ProductController 或 BehaviorController）：

```java
@Operation(summary = "我的商品浏览历史（需登录，R-3）")
@GetMapping("/api/products/browse-history")
public Result<List<ProductVO>> browseHistory(
        @RequestParam(defaultValue = "20") Integer limit) {
    Long userId = LoginUserContext.getCurrentUserId();
    // user_behavior type=1 最近浏览商品（去重，limit≤50）
    // → 关联 product 组装 ProductVO（复用 listPage 的 VO 转换）
    return Result.success(productService.listBrowseHistory(userId, limit));
}
```

实现要点（ProductService.listBrowseHistory）：
- 查 `user_behavior WHERE user_id=? AND behavior_type=1 ORDER BY create_time DESC LIMIT 100`
- 按 productId 去重取前 limit，批量 `productMapper.selectBatchIds`
- 过滤已下架/已删，按浏览时间倒序返回 ProductVO（含 mainImage/price）

**② 前端 History.vue 改造**：
- 数据源改为 `getBrowseHistory()`（api/product.js 新增）
- 模板改商品卡片（图片/名称/价格，点击跳详情），保留时间显示（可用 behavior create_time 或省略）
- 搜索历史保留在搜索页的"最近搜索"标签（D-3 已实现），不重复

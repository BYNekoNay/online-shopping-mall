# 项目脚手架与环境规范

> **版本状态**：v0.1 规划版，基于毕业设计任务书编制，尚未与实际代码核对，详见 `00-文档说明.md`。
>
> **本文档定位**：`08-开发指南.md` §2.1/§2.4/§3.1/§3.6 给出了工程目录结构与"安装JDK/Node.js"级别的环境说明，但未固定具体版本号、根包名与配置文件内容，导致不同人（或不同AI编码工具）实现时可能选择不兼容的版本或虚构包名。本文档是**唯一的版本与脚手架事实来源**：Java 根包名、JDK/Node 版本、后端全部依赖坐标与版本号、前端全部依赖版本号、`pom.xml`/`application.yml`/`package.json` 的完整骨架均在此固定，其余文档中出现的版本描述（如"JDK 8或17"“Node 16/18”）以本文档为准进行收敛，不再作为可选项。

## 2. 后端依赖版本清单

### 2.1 `pom.xml` 完整骨架

```xml

  <modelVersion>4.0.0</modelVersion>

  <parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>2.7.18</version>
  </parent>

  <groupId>com.pzhu</groupId>
  <artifactId>mall</artifactId>

  <packaging>jar</packaging>

    <java.version>17</java.version>
    <maven.compiler.source>11</maven.compiler.source>
    <maven.compiler.target>11</maven.compiler.target>

  <dependencies>
    <!-- Web -->
    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-web</artifactId>
    </dependency>

      <groupId>org.redisson</groupId>

      <version>3.27.2</version>
```

- Spring Boot 2.7.18 的 `spring-boot-starter-parent` 已管理 `spring-boot-starter-web`/`spring-boot-starter-data-redis`/`spring-boot-starter-validation`/`spring-boot-starter-test`/`lombok`/`spring-security-crypto` 的版本，上表未标注版本号的依赖均由父 POM 统一管理，**不要手动指定版本**，避免与 Spring Boot 官方管理的版本冲突；
- `knife4j` 一项若时间不允许可整体删除该依赖块，不影响其余模块，与 `08-开发指南.md` §2.4 "推荐但非强制"一致。

## 3. `application.yml` 完整骨架

```yaml
server:
  port: 8080

spring:
  application:
    name: mall
  datasource:
    url: jdbc:mysql://localhost:3306/mall?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
    username: root
    password: ${DB_PASSWORD:root}
    driver-class-name: com.mysql.cj.jdbc.Driver
  redis:
    host: localhost
    port: 6379
    password: ${REDIS_PASSWORD:}
    database: 0
  servlet:
    multipart:
      max-file-size: 10MB
      max-request-size: 20MB

mybatis-plus:
  mapper-locations: classpath*:mapper/**/*.xml
  configuration:
    map-underscore-to-camel-case: true
    log-impl: org.apache.ibatis.logging.stdout.StdOutImpl   # 开发环境打印SQL，生产环境移除
  global-config:
    db-config:
      logic-delete-field: isDeleted
      logic-delete-value: 1
      logic-not-delete-value: 0

jwt:
  secret: ${JWT_SECRET:pzhu-mall-dev-0aa08406fe73966ebf7e24b35ed2c333a130617c0ce9a1e0}
  expire-seconds: 604800   # 7天，对应11-后端开发详细文档.md §1.3 JwtUtil

mall:
  upload:
    dir: /data/mall/uploads     # 本地图片上传存储目录，对应09-接口规范.md §1.6
    base-url: http://localhost:8080/uploads
  order:
    timeout-minutes: 30         # 对应11-后端开发详细文档.md §4.5 订单超时自动取消
  stock:
    lock-wait-seconds: 3
    lock-lease-seconds: 10      # 未开启看门狗时的兜底值，见11-后端开发详细文档.md §4.2

logging:
  level:
    com.pzhu.mall: INFO
    com.pzhu.mall.modules.order: DEBUG
```

- `application-dev.yml`/`application-prod.yml` 通过 `spring.profiles.active` 覆盖 `datasource.password`/`redis.password`/`jwt.secret` 等环境相关配置，本骨架为通用基础配置（`application.yml`），敏感值建议走环境变量（如上表 `${DB_PASSWORD:root}` 写法：本地开发用默认值，生产环境通过环境变量覆盖）；
- `jwt.expire-seconds`/`mall.order.timeout-minutes` 等业务参数在此集中配置，`11-后端开发详细文档.md` 中提到的"如30分钟""如10分钟"等示例值均以本文件中实际配置的值为准，避免代码中出现魔法数字。

## 5. 环境变量与敏感配置管理

- 后端敏感配置（数据库密码、Redis密码、JWT密钥）通过环境变量注入（见 §3 `${DB_PASSWORD:root}` 写法），本地开发使用默认值即可运行，**不需要额外的 `.env` 文件机制**（Spring Boot 原生支持环境变量覆盖 `application.yml` 占位符）；
- 前端 `.env.development`/`.env.production` 按 `08-开发指南.md` §3.6 约定仅存放 `VITE_API_BASE_URL` 一类非敏感的构建期配置，格式：

```
# .env.development
VITE_API_BASE_URL=/api
```

## 1. 批次 A：答辩高性价比项

## A-1 浏览历史推荐位

### 1.1 用途与目标

任务书三.3 消费者模块"个性化推荐"明确列出 4 种推荐：**猜你喜欢（UserCF）、相似商品推荐（ItemCF）、浏览历史推荐、购买推荐**。当前系统仅实现前 2 种 + 热门兜底，浏览历史/购买推荐缺位。本项新增"浏览历史推荐"区块：

- 基于用户**最近浏览**（user_behavior type=1）的商品，用 ItemCF 相似度召回"你浏览过的同类商品"
- 与"猜你喜欢"（UserCF 全局）互补，避免推荐位内容重叠
- 仅登录用户可见；未登录不展示该区块（避免接口无意义调用）

### 1.2 页面结构与交互流程

```
首页 Index.vue
├─ banner 轮播
├─ 限时活动
├─ 全部分类
├─ 猜你喜欢（RecommendList mode="guess"）     ← 已有
└─ 浏览历史推荐（RecommendList mode="history"） ← 新增（v-if="isLogin"）
```

**交互流程**：
1. 用户登录后进入首页 → `isLogin` 为真 → 渲染"浏览历史推荐"区块
2. `RecommendList` 组件 `mode="history"` 挂载 → 调 `GET /recommend/history?num=10`
3. 后端返回 VO 列表 → 渲染商品卡片（复用现有卡片样式）
4. 曝光/点击上报：`source = "home-history"`（扩展 behavior 上报语义）
5. 区块空（无浏览记录/无相似商品）→ 显示 `el-empty`，或隐藏整个区块

#### 1.3.2 服务层实现（RecommendService 新增）

```java
/** 浏览历史推荐：基于最近浏览商品的 ItemCF 相似召回 */
public List<RecommendVO> historyBased(Long userId, Integer num) {
    int limit = num != null ? Math.min(Math.max(num, 1), 50) : DEFAULT_RECOMMEND_NUM;

    // 1. 取最近浏览的商品（user_behavior type=1，按 create_time 倒序，去重取前 10 个商品）
    List<UserBehavior> recent = userBehaviorMapper.selectList(
            new LambdaQueryWrapper<UserBehavior>()
                    .eq(UserBehavior::getUserId, userId)
                    .eq(UserBehavior::getBehaviorType, 1)
                    .orderByDesc(UserBehavior::getCreateTime)
                    .last("LIMIT 50"));
    if (recent.isEmpty()) {
        return List.of();                       // 无浏览历史，区块不显示
    }
    Set<Long> viewedIds = recent.stream()
            .map(UserBehavior::getProductId)
            .filter(Objects::nonNull)
            .limit(10)
            .collect(Collectors.toCollection(LinkedHashSet::new));

    // 2. 对每个浏览过的商品计算 ItemCF 相似，按相似度得分汇总
    Map<Long, Double> scoreAgg = new HashMap<>();
    Map<Long, Integer> countAgg = new HashMap<>();
    for (Long pid : viewedIds) {
        Map<Long, Double> sim = recommendCalculateService.computeSimilarProducts(pid, 5);
        for (Map.Entry<Long, Double> e : sim.entrySet()) {
            if (viewedIds.contains(e.getKey())) continue;   // 排除已浏览商品
            scoreAgg.merge(e.getKey(), e.getValue(), Double::sum);
            countAgg.merge(e.getKey(), 1, Integer::sum);
        }
    }
    if (scoreAgg.isEmpty()) {
        return List.of();                       // 无相似结果
    }
    // 归一化：平均相似分排序（多商品投票比单商品高分更可信）
    List<Map.Entry<Long, Double>> ranked = scoreAgg.entrySet().stream()
            .sorted((a, b) -> Double.compare(
                    b.getValue() / countAgg.get(b.getKey()),
                    a.getValue() / countAgg.get(a.getKey())))
            .limit(limit)
            .collect(Collectors.toList());

    // 3. 批量加载商品并过滤下架
    List<Long> productIds = ranked.stream().map(Map.Entry::getKey).collect(Collectors.toList());
    List<Product> products = productMapper.selectBatchIds(productIds);
    Map<Long, Product> pm = products.stream()
            .filter(p -> Integer.valueOf(1).equals(p.getStatus()))
            .collect(Collectors.toMap(Product::getId, p -> p));
    List<RecommendVO> vos = new ArrayList<>();
    for (Map.Entry<Long, Double> e : ranked) {
        Product p = pm.get(e.getKey());
        if (p != null) {
            vos.add(RecommendVO.from(p, e.getValue() / countAgg.get(e.getKey()), 2)); // algoType=2 ItemCF
        }
    }
    return vos;
}
```

**实现要点**：
- 依赖注入新增：`UserBehaviorMapper`（推荐模块暂未引入，需 `@Resource` 注入）
- 复用 `RecommendCalculateService.computeSimilarProducts(productId, limit)`（已有 ItemCF 计算，返回 `Map<Long, Double>`）
- 不做 Redis 缓存：浏览历史是准实时数据，实时计算成本低（每商品仅 TOP5 相似）；若压测发现慢可后续加 `history:{userId}` ZSet + 24h TTL（与 guessYouLike 同构）
- 性能：最多 10 商品 × 每次 5 相似 = 50 次内存计算，可接受

#### 1.3.3 控制器（RecommendController 新增）

```java
@Operation(summary = "浏览历史推荐（需登录）")
@GetMapping("/history")
public Result<List<RecommendVO>> historyBased(
        @RequestParam(defaultValue = "10") Integer num) {
    Long userId = LoginUserContext.getCurrentUserId();
    if (userId == null) {
        return Result.success(List.of());       // 未登录（理论上拦截器已拦，双保险）
    }
    return Result.success(recommendService.historyBased(userId, num));
}
```

### 1.5 数据流转


### 1.6 错误处理与边界情况

| 场景 | 行为 |
|---|---|
| 未登录访问 | JwtInterceptor 10002；控制器双保险返回空列表 |
| 无浏览历史 | 返回 `[]`，前端区块显示 el-empty |
| 浏览商品已下架 | `filter(status==1)` 过滤；结果不足 num 条就少返回 |
| 浏览商品无相似商品 | 返回 `[]`（不降级到热门，避免与猜你喜欢重复） |
| num 越界（<1 或 >50） | 服务端钳制到 [1,50]（复用 guessYouLike 模式） |
| user_behavior 有重复浏览 | `LinkedHashSet` 去重，保留最新 |
| Redis 不可用 | 本接口不走 Redis，天然免疫 |

### 1.7 性能与安全

- **性能**：无缓存时单次最多 10×5=50 次相似计算（内存 Map 操作，<5ms）；行为查询带 `LIMIT 50` + 索引（user_id, behavior_type, create_time）
- **安全**：IDOR——只查 `userId` 自己的行为；`num` 钳制防超大返回
- **扩展**：后续若需"购买推荐"，同构新增 `mode="purchase"`（type=3 行为），一行分支扩展

## A-2 促销范围收紧

### 2.1 用途与目标

**问题**：`PromotionService.validatePromotion`（M-06）允许 scope ∈ {PRODUCT, CATEGORY, SHOP}，但 `listActiveByShop` 的查询**硬编码 `.eq(Promotion::getScope, "SHOP")`** —— 管理端若创建 PRODUCT/CATEGORY 级促销，订单计算时完全不匹配，**创建后不生效**，属隐性 bug。

**目标**：消除"建了不生效"，采用**方案 1（收紧校验）**：促销范围仅允许 SHOP（与计算逻辑一致）。成本 0.5h，无行为破坏。

### 2.2 实现要点（PromotionService.validatePromotion）

```java
// 原校验（宽松）：
//   if (p.getScope() == null || p.getScope().isBlank()) { throw ... }
// 收紧为：
if (p.getScope() == null || p.getScope().isBlank()) {
    throw new BusinessException(ErrorCode.PARAM_ERROR, "促销范围 scope 不能为空");
}
if (!"SHOP".equals(p.getScope())) {
    throw new BusinessException(ErrorCode.PARAM_ERROR,
            "当前版本促销范围仅支持 SHOP（店铺级）；PRODUCT/CATEGORY 级为后续扩展");
}
if (p.getScopeId() == null) {
    throw new BusinessException(ErrorCode.PARAM_ERROR, "促销范围 scopeId（店铺ID）不能为空");
}
```

**存量数据处理**（scripts 提示）：若库中已有 PRODUCT/CATEGORY 促销，SQL 统一置 `status=0` 下线：

```sql
UPDATE promotion SET status = 0 WHERE scope IN ('PRODUCT','CATEGORY');
```

### 3.2 文档内容（docs/19-v1.0-发布说明.md 新增"安全与营销规则说明"小节）

```markdown
## 安全架构说明
### CSRF 防护
系统采用 JWT 无状态认证：客户端将 Token 存放于 localStorage，
所有请求经 axios 拦截器统一附加 `Authorization: Bearer <token>` 头。
跨站请求（CSRF）无法在无用户交互的情况下伪造该自定义请求头（浏览器
跨域预检会拦截无 CORS 白名单的站点），因此本架构天然具备 CSRF 免疫，
无需 Cookie 会话式 CSRF Token。接口层仍以 JWT 签名校验 + 角色切面
双重防护保证请求真实性与权限隔离。

### 优惠券叠加规则
1. 同一店铺的同一订单分组仅可使用 1 张优惠券（下单时互斥选择）；
2. 优惠券折扣与积分抵扣可叠加（先券后积分）；
3. 优惠券与促销活动（限时折扣/满减/满赠/套餐）可叠加，
   但促销折扣在券前计算（商品价→促销价→券→积分）；
4. 跨店铺下单按店铺拆分订单数组，各分组独立用券，不跨店分摊。
```

## B-1 删除订单

### 4.1 用途与目标

任务书三.3 订单管理包含"**删除订单**"。当前仅消费者可取消，无删除能力。新增软删除（`is_deleted=1`），仅**已取消(5)/已退款(7)** 状态可删，保留订单流水供对账。

### 4.2 接口契约

```http
DELETE /api/orders/{id}
Authorization: Bearer <token>   // 消费者本人
```

| 参数 | 位置 | 说明 |
|---|---|---|
| id | path | 订单 ID |

**响应**：`{ "code": 0, ... }`

**错误码**：

| 场景 | 错误码 | message |
|---|---|---|
| 未登录 | 10002 | 未认证 |
| 订单不存在或已删除 | 40005 | 订单不存在 |
| 非本人订单 | 10003 | 无权操作该订单（IDOR 拦截，FORBIDDEN） |
| 状态不可删（待付款/待发货等） | 10001 | 仅已取消或已退款的订单可删除（PARAM_ERROR） |
| 并发重复删除 | 10001 | 订单状态已变化，请刷新后重试（PARAM_ERROR） |

### 4.3 服务层实现（OrderService 新增）

```java
@Transactional(rollbackFor = Exception.class)
public void deleteOrder(Long userId, Long orderId) {
    Order order = orderMapper.selectById(orderId);
    if (order == null || Integer.valueOf(1).equals(order.getIsDeleted())) {
        throw new BusinessException(ErrorCode.ORDER_NOT_FOUND, "订单不存在");
    }
    // IDOR 防护：仅本人可删
    if (!order.getUserId().equals(userId)) {
        throw new BusinessException(ErrorCode.FORBIDDEN, "无权操作该订单");
    }
    // 仅已取消(5) / 已退款(7) 可删
    if (order.getStatus() != 5 && order.getStatus() != 7) {
        // 审核修正：ORDER_STATUS_ERROR 枚举不存在，改用既有 PARAM_ERROR(10001)
        throw new BusinessException(ErrorCode.PARAM_ERROR, "仅已取消或已退款的订单可删除");
    }
    // 软删除（原子条件更新防并发）
    boolean updated = orderMapper.update(null,
            new LambdaUpdateWrapper<Order>()
                    .set(Order::getIsDeleted, 1)
                    .eq(Order::getId, orderId)
                    .eq(Order::getIsDeleted, 0));
    if (!updated) {
        throw new BusinessException(ErrorCode.PARAM_ERROR, "订单状态已变化，请刷新后重试");
    }
    log.info("[订单] 用户={} 删除订单={}", userId, orderId);
}
```

**实现要点**：
- 复用既有 `Order.isDeleted` 字段（已有，默认 0）
- 原子 UPDATE + WHERE `is_deleted=0` 防重复删除（与 doCancel 同构）
- **不释放库存/券/积分**：删除仅隐藏记录，已完成/已取消订单的资产已结算完毕
- ⚠️ **审核修正（必做）**：`ErrorCode` 无 `ORDER_STATUS_ERROR`，统一用 `PARAM_ERROR(10001)`；错误码表 §4.2 同步为 10001

```java
@Transactional(rollbackFor = Exception.class)
public void exchange(Long userId, Long goodsId, int quantity) {
    // 1. 校验商品存在且上架
    PointsGoods goods = pointsGoodsMapper.selectById(goodsId);
    if (goods == null || !Integer.valueOf(1).equals(goods.getStatus())) {
        throw new BusinessException(ErrorCode.PARAM_ERROR, "兑换商品不存在或已下架");
    }
    // 2. 校验库存（原子扣减防并发超兑）
    int updated = pointsGoodsMapper.update(null,
            new LambdaUpdateWrapper<PointsGoods>()
                    .setSql("stock = stock - " + quantity)
                    .eq(PointsGoods::getId, goodsId)
                    .eq(PointsGoods::getStatus, 1)
                    .ge(PointsGoods::getStock, quantity));
    if (updated == 0) {
        throw new BusinessException(ErrorCode.PARAM_ERROR, "兑换库存不足");
    }
    // 3. 校验并扣减用户积分（原子，points >= cost）
    int cost = goods.getPointsCost() * quantity;
    boolean pointsOk = userMapper.update(null,
            new LambdaUpdateWrapper<User>()
                    .setSql("points = points - " + cost)
                    .eq(User::getId, userId)
                    .ge(User::getPoints, cost)) > 0;
    if (!pointsOk) {
        // 回滚库存（原子归还）
        pointsGoodsMapper.update(null,
                new LambdaUpdateWrapper<PointsGoods>()
                        .setSql("stock = stock + " + quantity)
                        .eq(PointsGoods::getId, goodsId));
        throw new BusinessException(ErrorCode.PARAM_ERROR, "积分不足");
    }
    // 4. 写积分流水（type=5 兑换扣减）+ 兑换记录
    // 审核修正：PointsRecord 无 5 参构造且无备注字段（仅 id/userId/changeAmount/type/relatedOrderId/createTime），
    // 改用 setter 链；备注语义由 points_exchange_log.goods_name 快照承担
    PointsRecord record = new PointsRecord();
    record.setUserId(userId);
    record.setChangeAmount(-cost);
    record.setType(5); // 兑换扣减
    record.setCreateTime(LocalDateTime.now());
    pointsRecordMapper.insert(record);
    PointsExchangeLog log = new PointsExchangeLog();
    log.setUserId(userId);
    log.setGoodsId(goodsId);
    log.setPointsCost(cost);
    log.setGoodsName(goods.getName());
    pointsExchangeLogMapper.insert(log);
}
```

**要点**：库存扣减与积分扣减顺序（先库存后积分），积分不足时回滚库存；整体在同一事务，任一步异常自动回滚（DB 层）；幂等（重复提交由前端按钮 loading 防抖 + 可加 requestId）。

## C-4 物流公司信息维护

### 11.1 用途与目标

任务书 7.3"物流公司信息维护（顺丰、圆通、中通等）"。当前发货时 `company` 为自由文本。**最小实现**：管理端维护物流公司字典表，商家发货下拉选择。

### 11.2 数据模型

```sql
CREATE TABLE logistics_company (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  name        VARCHAR(50) NOT NULL COMMENT '公司名称（顺丰/圆通/中通）',
  code        VARCHAR(20) NOT NULL COMMENT '公司编码（对接物流API用）',
  sort        INT NOT NULL DEFAULT 0,
  status      TINYINT NOT NULL DEFAULT 1,
  create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
) COMMENT '物流公司字典';
```

### 11.3 接口与前端

```http
GET  /api/admin/logistics-companies          // 管理端列表
POST /api/admin/logistics-companies          // 新增
PUT  /api/admin/logistics-companies/{id}     // 更新
GET  /api/merchant/logistics-companies       // 商家发货下拉选项
```

- 商家发货页（`merchant/order/List.vue` 发货 Dialog）：company 从下拉选择替代自由输入
- 管理端：`admin/logistics/Companies.vue` 简单 CRUD
- **决策点**：若维持"模拟物流"口径，本项可仅做下拉字典（不做轨迹对接），价值在于满足"公司信息维护"条款

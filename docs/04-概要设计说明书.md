# 概要设计说明书

> **版本状态**：v0.1.2 规划版，基于毕业设计任务书编制，尚未与实际代码/审计结果核对，详见 `00-文档说明.md`。

## 1. 设计目标与原则

### 1.1 设计目标

在满足 `03-软件需求规格说明书.md` 所有功能性与非功能性需求的前提下，构建一个结构清晰、易于维护和扩展的前后端分离电商系统，并将协同过滤推荐算法作为独立可演进的能力模块。

### 1.2 设计原则

- **分层解耦**：表现层、业务层、数据层、算法层职责清晰，互不越界；
- **模块化**：按业务领域（用户、商品、订单、推荐、营销、统计、系统管理）划分模块，降低耦合；
- **高内聚低耦合**：推荐算法引擎作为独立模块，通过明确接口与主业务交互，便于后续替换/升级算法；
- **安全默认开启**：鉴权、参数校验、防注入措施在架构层面统一收口（网关/拦截器层），而非依赖各业务模块自行实现；
- **面向高并发的关键路径设计**：下单、库存扣减等关键路径在架构上预留缓存与分布式锁能力。

## 2. 总体架构

系统采用 **B/S 架构、前后端分离**模式，整体分为四层：

```
┌─────────────────────────────────────────────┐
│  表现层：Vue3 + Element Plus                  │
│  （消费者端 / 商家端 / 管理员端，三套前端应用或    │
│   基于角色的路由与权限动态渲染）                 │
└───────────────────┬───────────────────────────┘
                     │ HTTPS + JWT（Axios 请求）
┌───────────────────▼───────────────────────────┐
│  业务层：Spring Boot RESTful API               │
│  用户服务 / 商品服务 / 订单服务 / 营销服务 /       │
│  统计服务 / 系统管理服务                        │
└───────┬───────────────────────────┬────────────┘
        │                           │
┌───────▼────────┐          ┌───────▼────────────┐
│  数据层          │          │  算法层              │
│  MySQL 8.0       │◄────────►│  协同过滤推荐引擎     │
│  （业务数据持久化）│  行为数据 │  （UserCF/ItemCF/混合）│
│  Redis           │          │  离线计算 + 缓存写回  │
│  （缓存/分布式锁）│          │                     │
└─────────────────┘          └─────────────────────┘
```

- **表现层**：Vue3 + Element Plus 构建用户界面，Axios 处理网络请求，ECharts 渲染数据可视化图表；响应式布局适配 PC 端为主，兼顾常见移动端分辨率。
- **业务层**：Spring Boot 提供 RESTful API，处理鉴权、参数校验、业务规则、事务控制。
- **数据层**：MySQL 存储用户、商品、订单等业务数据；Redis 缓存热点商品数据、用户行为数据、推荐结果，并提供分布式锁能力。
- **算法层**：协同过滤算法引擎，负责用户/商品相似度计算与推荐结果生成，通过离线批处理 + Redis 缓存实现"准实时"推荐更新，与业务层通过内部服务接口或应用内模块调用交互。

## 3. 模块划分

### 3.1 前端模块（按角色划分应用/路由分区）

| 模块 | 说明 |
|---|---|
| 消费者端 | 首页/分类、商品详情、搜索、购物车、下单、订单、用户中心、推荐位组件 |
| 商家端 | 店铺管理、商品管理、订单管理、数据统计（ECharts图表） |
| 管理员端 | 用户管理、商品审核、商家管理、数据看板、系统管理 |
| 公共模块 | 登录/注册、权限路由守卫、通用组件（分页、上传、富文本编辑器）、Axios 封装（请求拦截、Token 携带、错误统一处理） |

### 3.2 后端模块（按业务领域划分，单体应用内分包）

| 模块 | 职责 | 关键实体 |
|---|---|---|
| 用户与鉴权模块 | 注册/登录、JWT签发与校验、角色权限、用户信息管理 | user、role |
| 商品模块 | 商品/SKU/分类管理、上下架、审核状态流转 | product、sku、category |
| 购物车与订单模块 | 购物车、下单、库存扣减、订单状态流转、支付回调、退款售后 | cart、order、order_item、payment |
| 营销模块 | 优惠券、促销活动、积分 | coupon、promotion、points |
| 物流模块 | 物流公司信息、物流单号、物流轨迹查询（对接快递100）、商家运费模板配置（按区域/包邮门槛计算下单运费） | logistics、freight_template |
| 用户行为与推荐模块 | 行为采集（浏览/收藏/购买/评价）、UserCF/ItemCF 相似度计算、推荐结果生成与缓存 | user_behavior、user_score、recommend_result |
| 统计模块 | 商家经营数据统计、平台GMV/转化率/推荐效果统计 | 基于订单/行为数据的聚合查询 |
| 系统管理模块 | 商家入驻审核、系统参数、操作日志、数据字典 | operation_log、dict |

模块间通过 Service 接口调用，购物车/订单模块在写入用户行为数据后，通知（同步写入或异步消息，视工程量选择）用户行为与推荐模块用于后续相似度计算。

## 4. 技术选型说明

| 技术 | 选型理由 |
|---|---|
| Spring Boot 2.x | 简化 Spring 配置，内嵌容器快速启动，生态成熟，适合毕业设计周期内快速交付 |
| MyBatis-Plus | 在 MyBatis 基础上提供通用 CRUD、分页插件、条件构造器，减少样板代码，同时保留原生 SQL 灵活性以支持复杂统计查询 |
| MySQL 8.0 | 关系型数据库，事务支持完善，满足订单等强一致性场景；支持窗口函数便于统计类查询（如销售趋势） |
| Redis | 满足热点数据缓存、推荐结果缓存、分布式锁（防超卖）、限流等多种需求，单一组件覆盖多个非功能性需求 |
| JWT | 无状态鉴权，适合前后端分离架构，避免服务端 Session 存储压力 |
| Vue3 + Element Plus | Vue3 组合式 API 便于逻辑复用，Element Plus 提供丰富的中后台组件，加速商家端/管理员端开发 |
| Axios | 成熟的前端 HTTP 客户端，支持拦截器统一处理鉴权 Token 与错误码 |
| ECharts | 功能全面的可视化图表库，满足销售趋势、GMV看板等统计展示需求 |
| 协同过滤（UserCF+ItemCF） | 经典推荐算法，原理清晰、可解释性强，适合结合毕业论文进行算法层面的分析与改进（冷启动、混合权重） |

## 5. 部署架构（规划）

```
用户浏览器
   │ HTTPS
   ▼
Nginx（反向代理 + 静态资源托管，可选 CDN 扩展）
   │
   ├── 前端静态资源（Vue3 构建产物）
   │
   ▼
Spring Boot 应用（单体部署，可选多实例 + 负载均衡）
   │
   ├── MySQL 8.0（主库，读写分离为可选扩展）
   │
   └── Redis（缓存 + 分布式锁 + 定时任务协调）
```

> 演示/答辩阶段可采用单机部署（Nginx + Spring Boot + MySQL + Redis 均部署于同一台云服务器），生产化演进方向（读写分离、CDN、多实例）在任务书中标注为"可选扩展"，本设计预留架构扩展空间但不在本阶段强制实现。

## 6. 关键设计决策

### 6.1 推荐结果的"准实时"更新策略

- 用户相似度矩阵/物品相似度矩阵的**全量计算**采用离线批处理（定时任务，如每日/每小时触发一次），避免高频计算拖慢主业务链路；
- 用户产生新的行为数据（浏览/收藏/购买/评价）后，采用**增量更新 + 缓存**策略：将最新行为写入 Redis 供推荐结果的局部调整参考，推荐主结果仍以最近一次离线计算为基础，实现"准实时"而非"强实时"；
- 推荐结果统一写入 Redis（`recommend_result` 缓存），设置合理过期时间，接口读取时优先命中缓存，未命中则回源触发计算或返回兜底的热门商品推荐。

### 6.2 库存超卖防护

- 下单时对 SKU 库存执行「Redis 分布式锁 + 预扣减」：先在 Redis 中原子性地扣减库存计数，成功后再创建订单与执行数据库库存扣减；
- 若支付超时，通过定时任务释放预扣减库存并将订单置为"已取消"；
- 发货后库存不可逆向恢复，仅在退货流程完成后恢复库存，保证库存流转与订单状态严格对应（详见 `05-详细设计说明书.md`）。

### 6.3 鉴权与权限设计

- 登录成功后签发 JWT，前端在 Axios 请求头携带 Token；
- 后端网关/拦截器层统一校验 Token 有效性并解析角色信息，按角色进行接口级权限校验（消费者/商家/管理员的接口相互隔离）；
- 商家、管理员的敏感操作（审核、下架、禁用用户等）需要二次的角色权限判断，防止越权访问。

### 6.4 数据统计设计

- 商家/管理员的统计看板优先使用 MySQL 聚合查询 + 定时预计算（如日终统计任务生成汇总表），避免复杂统计 SQL 在高峰期直接压向明细表；
- ECharts 图表数据接口返回统一的时间序列/分类汇总数据结构，前端图表组件与数据结构解耦，便于复用。

## 7. 与需求的对应关系

本概要设计中的模块划分与架构决策，覆盖 `03-软件需求规格说明书.md` 中全部功能性需求模块（消费者/商家/管理员/营销支付物流）及全部非功能性需求（性能、安全、高并发、数据一致性）。详细的表结构、算法伪代码、接口清单见 `05-详细设计说明书.md`。

# 接口规范

> **版本状态**：v0.1 规划版，基于毕业设计任务书编制，尚未与实际代码核对，详见 `00-文档说明.md`。
>
> **本文档定位**：`05-详细设计说明书.md` §5 给出的是"节选核心接口"的概要索引；本文档在其基础上给出正式的、字段级的 REST API 契约，是前后端联调（见 `08-开发指南.md` §4）的唯一依据。开发中接口如需新增或调整字段，**先修改本文档，再改代码**，与 `10-数据库规范.md` 保持"先文档后实现"的一致纪律。数据库字段的完整定义见 `10-数据库规范.md`，本文档不重复列出实体全部字段，仅给出接口级别的请求/响应结构。

## 1. 通用约定

### 1.1 基础信息

- Base URL：`/api`（本地联调经 `08-开发指南.md` §4.2 的代理转发到后端真实端口；暂不在路径中加版本号前缀，未来如需不兼容升级，整体切换为 `/api/v2`）
- 数据格式：请求/响应均为 `application/json`；文件上传接口使用 `multipart/form-data`（见 §1.6）
- 字符编码：UTF-8

### 1.2 统一响应结构

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

- `code`：`0` 表示业务成功；非 `0` 见 §4 错误码表。HTTP 状态码固定返回 `200`（鉴权/权限类问题除外，见 §1.4），业务级成功或失败均通过 `code`/`message` 表达；
- 前端统一按 `code` 做逻辑判断，不依赖 `message` 文案（`message` 仅用于展示提示）；
- `data`：成功时的业务数据，无数据时为 `null`；**列表类接口即使结果为空也返回 `[]`，不返回 `null`**（呼应 `08-开发指南.md` §4.4）。

### 1.3 分页统一结构

请求参数（Query）：

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| pageNum | int | 否 | 1 | 页码，从1开始 |
| pageSize | int | 否 | 10 | 每页条数，上限100 |

响应 `data` 结构：

```json
{
  "total": 128,
  "pageNum": 1,
  "pageSize": 10,
  "pages": 13,
  "records": []
}
```

### 1.4 鉴权与状态码

- 除白名单接口（下表标注"公开"的接口）外，均需在请求头携带 `Authorization: Bearer {JWT}`；
- `401 Unauthorized`：未登录或 Token 失效/过期，前端统一跳转登录页并清空本地登录态；
- `403 Forbidden`：已登录但角色/资源归属权限不足（如消费者访问商家接口、商家操作非本店铺的商品/订单）；
- `404 Not Found`：仅用于路径本身不存在，区别于"业务查询数据为空"（后者仍返回 `200` + `code=0` + `data=null`）；
- 除以上三类外的业务异常，统一返回 `200` + 非 `0` 的 `code`，不用 4xx/5xx 表达业务错误，避免前端同时维护两套错误处理逻辑。

### 1.5 幂等性约定

- `POST /api/orders`（提交订单）、支付发起与支付回调接口需支持幂等：订单确认页生成的 `requestId` 随下单请求提交，后端对短时间内相同 `requestId` 的重复请求直接返回首次结果，不重复创建订单/不重复扣库存；
- 支付回调接口先校验订单当前状态，已处理过的回调直接返回成功，不重复执行状态流转与库存扣减。

### 1.6 文件上传

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/upload/image | 通用图片上传（商品主图/多图、富文本详情图、头像、Logo均复用此接口），`multipart/form-data`，返回可访问的图片URL，供其他表单字段引用 |

### 1.7 命名与格式约定

- 字段命名：小驼峰（camelCase），与数据库下划线命名的映射由 MyBatis-Plus 自动完成；
- 时间格式：`yyyy-MM-dd HH:mm:ss`；
- 金额字段：序列化为固定两位小数的数值（如 `12.50`），后端统一使用 `BigDecimal`，避免浮点误差；
- 布尔字段：`true`/`false`，不与 `0`/`1` 混用。

## 2. 完整接口清单

### 2.1 用户与鉴权模块

**POST /api/auth/register**（公开）— 用户注册

请求体：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| username | string | 是 | 登录名，唯一 |
| password | string | 是 | 明文密码，后端 BCrypt 加密存储 |
| nickname | string | 是 | 昵称 |
| role | int | 是 | 1-消费者，2-商家 |
| phone | string | 否 | |
| email | string | 否 | |

响应 `data`：`{ "userId": 1001 }`

> `role=2`（商家）注册后**仅创建用户账号，不自动创建店铺**——`shop` 表要求 `merchant_user_id` 唯一，用户注册成功后必须调用下方 `POST /api/merchant/shop/apply` 提交入驻申请，由管理员审核通过后才拥有可用店铺（`shop.status=1`）。商家用户在店铺审核通过前登录后仅能看到"入驻申请"页面，`GET /api/merchant/shop`、商品/订单等其余商家接口在店铺不存在或未通过审核时统一返回 `10004` 资源不存在（前端据此跳转到入驻申请页，见 `13-前端开发详细文档.md` §3.1）。

**POST /api/auth/login**（公开）— 登录

请求体：`{ "username": "", "password": "" }`

响应 `data`：

```json
{
  "token": "xxx.yyy.zzz",
  "userId": 1001,
  "role": 1,
  "nickname": "..."
}
```

错误码：`20001` 用户名或密码错误、`20002` 账号已被禁用。

**GET /api/user/profile** — 获取当前用户信息

响应 `data`：`{ "id","username","nickname","avatar","phone","email","role" }`（对应 `10-数据库规范.md` `user` 表只读字段，不含 `password`）。

**PUT /api/user/profile** — 更新个人信息

请求体：`{ "nickname","avatar","phone","email" }`（均选填，仅更新传入字段）。

**GET/POST/PUT/DELETE /api/user/addresses** — 收货地址增删改查

请求体（POST/PUT）：`{ "receiver","phone","province","city","district","detail","isDefault" }`。

### 2.2 商品与推荐模块（公开只读接口）

**GET /api/products** — 商品列表

请求参数（Query）：`categoryId`、`minPrice`、`maxPrice`、`sort`（`sales`/`price_asc`/`price_desc`/`new`）、`pageNum`、`pageSize`。

响应 `data`：分页结构，`records` 每项：`{ "id","name","mainImage","price","originalPrice","sales" }`。

**GET /api/products/{id}** — 商品详情

响应 `data`：`{ "id","shopId","categoryId","name","mainImage","images":[],"detail","price","originalPrice","stock","sales","skuList":[{ "id","specJson","price","stock" }],"activePromotion":null }`。`activePromotion` 为该商品当前命中的生效促销（`PromotionService` 按 `scope`/`scope_id` 匹配 `10-数据库规范.md` `promotion` 表且 `status=1`/在 `start_time`~`end_time` 区间内的记录，多个命中时取 `10-数据库规范.md` §2.4.2 "同类型取抵扣金额最大"规则筛选后的单条），无命中时为 `null`；结构：`{ "id","type","name","ruleJson" }`（`ruleJson` 原样透出，前端按 `type` 自行渲染折扣/满减/满赠/套餐文案，具体渲染规则见 `13-前端开发详细文档.md` §2.3）。

**GET /api/products/search** — 关键词搜索

请求参数：`keyword`（必填）、`categoryId`、`minPrice`、`maxPrice`、`sort`、`pageNum`、`pageSize`。响应结构同 §2.2 商品列表；搜索成功后异步写入 `search_history`。

**GET /api/user/search-history** — 获取当前用户搜索历史（需登录）

响应 `data`：`[{ "keyword","createTime" }]`（按时间倒序，默认最近20条）。

**DELETE /api/user/search-history** — 清空当前用户搜索历史（需登录）

**GET /api/recommend/guess-you-like**（公开，可选登录：携带合法 Token 返回个性化推荐，不携带或未登录返回热门兜底）— 猜你喜欢

- 该接口在 `JwtInterceptor` 白名单中（对应 `11-后端开发详细文档.md` §1.3 的"公开接口"），未携带 `Authorization` 头或 Token 无效时**不返回401**，而是按未登录处理直接走热门兜底，不中断请求；携带合法 Token 时正常解析出 `userId` 并返回个性化结果；

请求参数：`num`（返回条数，默认10）。

响应 `data`：`[{ "productId","name","mainImage","price","score","algorithmType" }]`，`algorithmType` 含义见 `10-数据库规范.md` `recommend_result` 表。

**GET /api/recommend/similar/{productId}**（公开）— 相似商品推荐

响应 `data`：结构同上，`algorithmType` 固定为 2（ItemCF）。

### 2.4 订单与支付模块（需登录）

**POST /api/orders** — 提交订单（含库存预扣减，见 `05-详细设计说明书.md` §4.1/§4.2）

请求体：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| addressId | long | 是 | |
| cartItemIds | long[] | 是（与productItems二选一） | 从购物车结算，可包含跨店铺的多个商品 |
| productItems | array | 否 | 立即购买场景：`[{ "productId","skuId","quantity" }]` |
| couponId | long | 否 | 使用的优惠券；**跨店铺下单时优惠券仅可抵扣其归属店铺（或平台券抵扣全部店铺）拆分出的那一笔子订单，不可跨店铺共用**，具体归属判断见 `10-数据库规范.md` `coupon.shop_id` |
| usePoints | boolean | 否，默认false | 是否使用积分抵扣；为 `true` 时按 `10-数据库规范.md` §2.4.3 "订单抵扣"规则（100积分抵1元，不超过商品金额50%）用光当前 `user.points` 能抵扣的最大额度，暂不支持指定抵扣积分数量；**跨店铺拆单时积分只抵扣拆分出的第一笔子订单**（按 `shopId` 分组后的数组顺序），不重复抵扣多笔，避免同一积分被多个子订单重复计算 |
| requestId | string | 是 | 幂等标识，见 §1.5 |

响应 `data`：**订单数组**（对应 `05-详细设计说明书.md` §2.2 "跨店铺下单按店铺拆分为多个订单"的设计决策——同一次提交按 `cartItemIds`/`productItems` 中商品所属 `shop_id` 分组，每组生成一个订单；单店铺下单时数组长度恒为1，前端不应假设固定长度）：

```json
[
  { "orderId": 1001, "orderNo": "20260706153000000001", "shopId": 10, "payAmount": 128.50, "freightAmount": 8.00, "promotionDiscountAmount": 5.00, "couponDiscountAmount": 10.00, "pointsDeductAmount": 5.00 },
  { "orderId": 1002, "orderNo": "20260706153000000002", "shopId": 11, "payAmount": 56.00, "freightAmount": 0, "promotionDiscountAmount": 0, "couponDiscountAmount": 0, "pointsDeductAmount": 0 }
]
```

- `payAmount = goodsAmount + freightAmount - promotionDiscountAmount - couponDiscountAmount - pointsDeductAmount`；`goodsAmount` 为商品金额小计，若命中 `promotion.type=1`（限时折扣）/`type=4`（组合套餐）已在下单时按促销价折算进各商品单价快照（不再单独体现为 `promotionDiscountAmount`），`promotionDiscountAmount` 字段仅体现 `type=2`（满减促销）产生的独立抵扣金额，两者叠加计算顺序见 `10-数据库规范.md` §2.4.2、`11-后端开发详细文档.md` §4.1；
- 若该分组命中 `promotion.type=3`（满赠）且赠品库存充足，本次下单会额外生成一条赠品明细（`order_item.is_gift=true`），可在 `GET /api/orders/{id}` 的 `items` 中看到，不体现在本接口的金额字段中（赠品不影响 `payAmount`）；
- `pointsDeductAmount` 仅第一笔子订单可能非零（见上方请求参数 `usePoints` 说明），其余子订单固定为 `0`；
- 幂等约定（§1.5）中的 `requestId` 对应**本次提交整体**（即拆分出的多个订单作为一个整体去重，不是每个子订单各自一个 `requestId`）；
- 支付：拆分出的多个订单**各自独立支付**，前端下单成功后需引导用户依次完成每个订单的支付（见 `13-前端开发详细文档.md` §2.5），后端不提供"一次支付多个订单"的合并支付接口；
- 若拆分后的某一子订单因库存不足等原因创建失败，已成功创建的其余子订单**不回滚**（不同店铺订单相互独立），失败的子订单在响应数组中省略，前端根据请求的 `cartItemIds`/`productItems` 数量与响应数组长度的差异，提示用户"部分商品下单失败"。

错误码：`40001` 库存不足、`40002` 商品已下架、`40003` 优惠券不可用。

**POST /api/orders/{id}/pay** — 发起模拟支付

请求体：`{ "payType": 1 }`（1-余额，2-模拟支付宝）

响应 `data`：`{ "paySuccess": true, "payNo": "..." }`

**GET /api/orders** — 订单列表

请求参数：`status`（可空，为空查全部）、`pageNum`、`pageSize`

**GET /api/orders/{id}** — 订单详情

响应 `data`：订单主体字段 + `items:[{ "id","productId","skuId","productName","productImage","price","quantity","isGift" }]`（订单明细，`isGift=true` 表示该行为满赠促销附赠的赠品，`price` 固定为 `0`，前端渲染为"赠品"标签而非金额，见 `13-前端开发详细文档.md` §2.6）+ `logistics`（如已发货）。

**PUT /api/orders/{id}/cancel** — 取消订单

**PUT /api/orders/{id}/confirm** — 确认收货

**POST /api/orders/{orderItemId}/review** — 商品评价

请求体：`{ "rating","content","images":[] }`

**POST /api/orders/{id}/refund** — 发起售后申请

请求体：`{ "type":1, "orderItemId":null, "reason":"" }`（`type` 1-仅退款，2-退货退款；`orderItemId` 为空表示整单售后）

### 2.5 商家端接口（需登录，角色=商家，且仅能操作本店铺资源）

**POST /api/merchant/shop/apply** — 提交商家入驻申请（对应 FR-A-06；仅当当前商家用户尚无 `shop` 记录，或此前申请被拒绝`status=2`后重新提交时可调用，已存在 `status∈{0,1,3}` 的记录时返回 `10001` 参数校验失败，提示"已有申请记录/已入驻"）

请求体：`{ "name","contactName","contactPhone","licenseNo","licenseImage","applyReason" }`（`licenseImage` 通过 `POST /api/upload/image` 上传后传URL）

响应 `data`：`{ "shopId": 10, "status": 0 }`（创建后 `status` 固定为0-待审核，等待管理员通过 `PUT /api/admin/shops/{id}/audit` 审核）

**GET /api/merchant/shop/apply-status** — 查询当前商家的入驻申请状态（商家登录后首先调用此接口判断跳转"入驻申请页"还是"店铺管理首页"）

响应 `data`：`{ "hasApplied": true, "shopId": 10, "status": 0, "rejectReason": null }`（`hasApplied=false` 表示尚未提交过申请）

**GET/PUT /api/merchant/shop** — 获取/更新店铺信息（含装修；仅 `status=1` 已通过审核的店铺可调用，否则返回 `10004`）

请求体（PUT）：`{ "name","logo","description","decorationConfig":{} }`

**GET/POST/PUT /api/merchant/freight-templates** — 运费模板列表/新建/编辑（对应 FR-M-11）

请求体（POST/PUT）：`{ "name","regionRuleJson":[{ "region":"华东","fee":8 }],"freeShippingThreshold":99,"defaultFee":10 }`

**POST /api/merchant/products** — 发布商品

请求体：`{ "categoryId","name","mainImage","images":[],"detail","price","originalPrice","stock","skuList":[{ "specJson","price","stock" }] }`

**PUT /api/merchant/products/{id}** — 编辑/上下架商品

请求体：与发布接口一致的可更新字段 + `{ "status" }`（上下架）

**PUT /api/merchant/products/batch** — 批量操作

请求体：`{ "productIds":[], "action":"ON_SHELF|OFF_SHELF|DELETE" }`

**GET /api/merchant/orders** — 订单列表（按状态筛选，仅本店铺）

**PUT /api/merchant/orders/{id}/ship** — 发货

请求体：`{ "logisticsCompany","trackingNo" }`

**PUT /api/merchant/refunds/{id}/audit** — 售后审核

请求体：`{ "approved": true, "handleRemark": "" }`

**GET /api/merchant/statistics/sales** — 销售统计

请求参数：`startDate`、`endDate`、`granularity`（`day`/`week`/`month`）

响应 `data`：`{ "totalAmount","totalOrders","trend":[{ "date","amount","orders" }] }`

**GET /api/merchant/statistics/top-products** — 热销商品TOP10

响应 `data`：`[{ "productId","name","sales","amount" }]`

**GET/POST/PUT /api/admin/coupons** — 优惠券模板管理（对应 FR-X-02 促销活动配置中的优惠券部分）

请求体（POST/PUT）：`{ "name","type","shopId","discountRule":{},"validFrom","validTo","stock" }`（`discountRule` 结构见 `10-数据库规范.md` §2.4.1；`type=1`新人券/`type=2`满减券时 `shopId` 传空表示平台券，`type=3`品类券/`type=4`店铺券时 `shopId` 必填；`type=3`品类券时 `discountRule.categoryId` 必填，其余 `type` 不传）

## 3. 完整接口清单的维护约定

以上清单覆盖 03/04/05 已定义的核心功能点，含营销模块（FR-X-02 促销活动、FR-X-03 积分体系）的消费者端只读接口与积分抵扣入口（见 §2.4 `POST /api/orders` 的 `usePoints`）；促销活动与优惠券的**新增/编辑管理入口**收拢在管理员端（§2.6），不在商家端开放（`promotion`/`coupon` 表未设计商家归属字段，跨店铺统一由平台运营配置，避免额外引入商家维度的权限校验复杂度）。

## 4. 错误码表

错误码按模块分段，前两位标识模块，后三位为序号，`0` 恒定表示成功。

| 区间 | 模块 |
|---|---|
| 10000-10999 | 通用（参数校验失败10001、未授权10002、无权限10003、资源不存在10004、系统繁忙10005） |
| 20000-20999 | 用户与鉴权（用户名或密码错误20001、账号已禁用20002、用户名已存在20003） |
| 30000-30999 | 商品（商品不存在30001、商品已下架30002、SKU不存在30003） |
| 40000-40999 | 订单（库存不足40001、商品已下架40002、优惠券不可用40003、订单状态不允许该操作40004、订单不存在40005） |
| 50000-50999 | 支付（支付失败50001、订单已支付50002、支付渠道异常50003） |
| 60000-60999 | 营销（优惠券已被领完60001、优惠券已过期60002、促销活动未生效60003） |
| 70000-70999 | 物流（运费模板不存在70001、物流查询失败70002） |
| 80000-80999 | 推荐与统计（推荐结果生成中80001，统计数据尚未生成80002） |
| 90000-90999 | 系统管理（参数不合法90001、字典项重复90002） |

> 完整错误码枚举应随开发进度在本文件持续补充，新增错误码需同时更新代码中的错误码枚举类，保持二者一致。

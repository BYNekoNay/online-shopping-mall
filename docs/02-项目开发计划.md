# 项目开发计划

> **版本状态**：v0.1.1 规划版，基于毕业设计任务书编制，尚未与实际代码/审计结果核对，详见 `00-文档说明.md`。

## 1. 项目概述

- **项目名称**：基于协同过滤算法的智能推荐网络商城的设计与实现
- **项目性质**：本科毕业设计
- **项目周期**：16 周
- **项目目标**：完成一个包含消费者、商家、管理员三大角色的 B2C 电商平台，核心特色为基于 UserCF/ItemCF 混合协同过滤算法的个性化商品推荐，交付完整可运行系统、数据库脚本、系统设计文档、测试报告、毕业论文及答辩材料。

## 2. 组织与人员分工

本项目为个人毕业设计，采用"学生开发 + 导师指导"模式：

| 角色 | 人员 | 职责 |
|---|---|---|
| 开发者 | 学生本人 | 需求分析、系统设计、前后端开发、算法实现、测试、文档与论文撰写 |
| 指导教师 | 导师 | 选题把关、阶段性检查、技术指导、论文与答辩指导 |

由于是单人开发，采用**迭代式开发**而非团队协作分工，各阶段间存在适度交叉重叠以提升效率（例如后端核心模块开发完成后即可并行开展前端对接）。

## 3. 进度计划

依据任务书第五节的16周总体安排，细化为可执行的周任务：

| 阶段 | 时间 | 主要任务 | 交付物 |
|---|---|---|---|
| 需求分析 | 第1-2周 | 调研现有电商/推荐系统、整理任务书需求、编写可行性研究报告与需求规格说明书 | `01-可行性研究报告.md`、`03-软件需求规格说明书.md` |
| 系统设计 | 第3-4周 | 概要设计（架构、模块划分、技术选型）、详细设计（数据库、算法、接口、流程） | `04-概要设计说明书.md`、`05-详细设计说明书.md` |
| 环境搭建 | 第5周 | 开发环境配置（JDK、MySQL、Redis、Node.js）、项目脚手架搭建（前后端工程）、数据库建表 | 可运行的空白工程、数据库脚本 |
| 后端开发 | 第6-10周 | 用户模块（注册/登录/JWT）、商品模块、订单模块、行为采集、UserCF/ItemCF 推荐算法实现 | 后端各模块接口 |
| 前端开发 | 第8-12周 | 消费者/商家/管理员页面、组件开发、接口对接、推荐结果展示、ECharts图表 | 前端各页面 |
| 系统测试 | 第13-14周 | 功能测试、接口测试、性能测试、推荐算法效果评估（准确率/召回率/覆盖率） | `06-测试计划.md` 执行结果、《测试报告》 |
| 论文撰写 | 第15-16周 | 毕业论文撰写、`07-用户操作手册.md` 完善、答辩材料准备、文档一致性回检 | 毕业论文、答辩PPT、v1.0 文档集 |

后端开发与前端开发存在第8-10周的重叠期，用于接口联调；系统测试阶段同步开展文档与代码的一致性回检工作（对应 `00-文档说明.md` 第5节流程）。

## 4. 资源需求

### 4.1 硬件环境

- 开发机：普通个人计算机（4核8G及以上）即可满足开发调试需求；
- 部署环境（可选）：云服务器 1 台（2核4G起步），用于演示部署。

## 5. 风险管理

| 风险编号 | 风险描述 | 可能性 | 影响 | 应对措施 |
|---|---|---|---|---|
| R1 | 协同过滤算法在数据稀疏（冷启动）阶段推荐效果不佳 | 高 | 中 | 采用热门商品推荐兜底、构建模拟行为数据集用于开发期验证算法逻辑正确性 |
| R2 | 单人开发周期紧张，前后端+算法+论文任务量大 | 中 | 高 | 严格按周计划推进，优先保证核心链路（浏览-下单-支付-推荐）可运行，非核心功能（如CDN加速、读写分离）标注为"可选扩展"降级处理 |
| R3 | 高并发场景（秒杀/促销）下的库存超卖 | 中 | 高 | 设计阶段即引入 Redis 分布式锁与库存预扣减机制（见 `05-详细设计说明书.md`） |
| R4 | 第三方物流查询 API（快递100）额度或稳定性限制 | 低 | 低 | 演示环境可使用模拟物流轨迹数据作为降级方案 |
| R5 | 文档与最终代码不一致 | 高（当前已发生，本文档集为规划版） | 中 | 按 `00-文档说明.md` 第5节流程，在代码完成与审计后统一回检更新为 v1.0 |
| R6 | 未开展正式代码审计 | 高（当前状态） | 中 | 在测试阶段（第13-14周）安排自查式安全测试（SQL注入、越权、XSS），并在有条件时引入外部/工具审计，结果记录于 `06-测试计划.md` 的审计发现记录表 |

## 6. 质量保证措施

- 编码规范：遵循阿里巴巴 Java 开发手册（后端）与 Vue3 官方风格指南（前端）；
- 版本管理：所有代码纳入 Git 管理，按功能模块提交，保留清晰的提交记录；
- 阶段评审：每个阶段结束后对照本文档与需求规格说明书进行自查，确保交付物覆盖任务书要求；
- 测试先行：核心业务逻辑（库存扣减、订单状态流转、算法相似度计算）编写单元测试。

## 7. 交付物清单

对应任务书"成果要求"，最终交付：

1. 完整可运行系统（前端 + 后端源代码）；
2. 数据库脚本（建表语句、初始化数据）；
3. 系统设计文档（本 `docs/` 目录全部文档，更新至 v1.0）；
4. 测试报告（基于 `06-测试计划.md` 执行后形成）；
5. 软件使用说明书（`07-用户操作手册.md`）；
6. 毕业设计论文及答辩材料（论文结构、图表规范须符合攀枝花学院本科毕业设计（论文）撰写规范要求，`docs/` 目录不承载论文正文，仅作为论文"系统设计与实现"章节的素材来源）。

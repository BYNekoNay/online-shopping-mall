## 1. 背景说明

### 1.1 被测系统
本项目为「基于协同过滤算法的智能推荐网络商城」，本科毕业设计，前后端分离架构：

| 端 | 技术栈 | 规模 |
|---|---|---|
| 后端 | **Java 17** / Spring Boot 2.7.18 / MyBatis-Plus 3.5.5 / MySQL 8.0 / Redis 7 / Redisson / JWT | 11 个业务模块，167 个源类 |
| 前端 | **JavaScript (Vue 3)** / Vite 5 / Element Plus / Pinia / Axios / Vitest | 三端（consumer/merchant/admin），44 个 .vue 页面 |

### 1.2 被测模块与用途
后端 11 模块：`user`（注册/登录/地址）、`shop`（店铺/入驻）、`product`（商品/SKU/分类/评价）、`cart`（购物车）、`order`（下单/支付/退款/超时，**核心交易**）、`recommend`（推荐算法，**创新点**）、`marketing`（券/促销/积分）、`logistics`（运费/物流）、`behavior`（行为埋点）、`statistics`（商家/平台统计）、`admin`（管理端）；横切：`security`（JWT/角色/防爆破）、`common`（Result/异常/Redis 键）。

### 1.3 现有测试资产
- **后端**：24 个测试类 / **207 用例**（JUnit 5 + Mockito），`./mvnw test` 全绿
- **前端**：3 个测试文件 / **14 用例**（Vitest）：request 封装、路由守卫、优惠券契约
- 集成：`MainChainIntegrationTest` + `FullChainIntegrationTest`
- 动态验证：docs/28 报告 10 项真实环境验证（并发压测/退款闭环/满赠）

## 5. 技术约束

### 5.1 环境约束
| 项 | 约束 |
|---|---|
| 后端测试运行 | `./mvnw test`（JAVA_HOME=D:\java，JDK 17 target）|
| 全量门禁 | `./mvnw verify`（含 checkstyle/spotbugs/jacoco），**需非沙箱模式**（沙箱限制 target 写盘）|
| 前端测试 | `npm test`（Vitest 1.6）|
| 数据库依赖 | 单元测试全部 Mockito mock，**不连真实 MySQL**；集成测试需本地 MySQL（root/123456）|
| Redis 依赖 | 单元测试 mock StringRedisTemplate；不依赖真实 Redis |

### 5.2 框架与工具
| 层 | 工具 |
|---|---|
| 后端单测 | JUnit 5 + Mockito + AssertJ（可选）|
| 后端 Controller | Spring MockMvc（@WebMvcTest 或轻量 standalone）|
| 覆盖率 | JaCoCo 0.8.11（`target/site/jacoco/`）|
| 前端 | Vitest + @vue/test-utils + happy-dom |
| CI | .github/workflows/ci.yml（frontend: lint+test+build；backend: mvn verify）|

### 5.3 代码规范
- 测试类命名：`XxxTest.java`，放 `src/test/java/com/pzhu/mall/modules/{模块}/` 对应包
- 测试方法命名：`方法_场景_期望`（如 `createOrder_stockNotEnough_throws`）
- 使用既有 `inject()` 反射注入工具（Mockito mock 注入私有字段），保持与现有测试风格一致
- mock 使用 `when/verify` 显式断言关键交互（扣库存、幂等键、日志）
- **禁止**：连接真实 DB/Redis 的单测、依赖执行顺序的用例、Thread.sleep 竞态

### 5.4 是否重构现有测试结构
**轻量重构**（不推翻现有）：
1. 抽取 `BaseServiceTest`（公共 mock 初始化 + inject 工具 + 常用 fixture）
2. 现有测试仅做命名对齐（不强制重写）
3. Controller 测试统一用 MockMvc standalone 模式（不加载 Spring 上下文，速度快）

| 时间不足 | 按优先级裁剪：P0 批次必达，P2 可延后；每批次独立验收 |
| 沙箱限制 target 写盘 | verify 在非沙箱模式运行（CI runner 无此问题）|

### 9.5 技术经验沉淀

| 坑 | 解法 |
|---|---|
| MyBatis-Plus `selectPage` 填充传入 page 参数（返回值被忽略） | mock 必须用 `thenAnswer` 设置传入 page 的 records |
| `reverseRangeWithScores` 返回 `Set<TypedTuple>` | mock 返回 `Collections.singleton/emptySet` |
| Mockito `verify(mapper).update(isNull(), any())` | null 匹配用 `isNull()` |
| `LoginUserContext` 是 ThreadLocal | 并发子线程内需重新 `set`，否则拿不到登录上下文 |
| 模拟 Redis Lua 原子扣减 | "先比较、不足返回 -1 且不改库存"（CAS 语义），失败扣减会导致库存漂移 |
| vi.mock factory 被提升 | mock 函数必须用 `vi.hoisted()` 声明（TDZ 错误） |
| @vue/test-utils 不导出 nextTick | 从 `vue` 导入 |
